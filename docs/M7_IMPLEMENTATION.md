# M7 本机联机实现与使用

日期：2026-10-15（Asia/Shanghai）。游戏：卡坦岛之三国争霸，沿用内测版1.4。本次请求为实现及微信公告，没有要求发送新的可玩压缩包，因此未自动递增发行号。

用户本轮确认先完成本机可验证部分，云服务器尚未准备。大厅允许直接加入房间，设置密码时才验证密码；采用持久访客凭据、掉线等待、存档不自动删除。真实多机、外网部署、清洁机器及长期容量验收仍须后续完成，不将本机检查记为 M7 全阶段完成。阶段退出状态保留在 [路线图](ROADMAP.md)。

## 启动与加入

构建使用 `tools/development/Build-M7.ps1`，运行使用 `tools/development/Play-M7.ps1`。默认程序位于 `.local/m7-v001/Builds/Windows/CatanM6.exe`；须保留整个 Windows 目录，包括旁边的 `Server` 自包含服务目录。现有单人四规则与当前 AI 继续使用同一客户端。

在游戏菜单进入联机界面，选择“局域网”，点击“启动本机服务”。房主核对界面上的 SHA-256 指纹并固定证书，再连接大厅。其他电脑可以“发现局域网”，或输入房主的 `https://局域网IP:47771` 地址；首次连接须通过房主可信渠道核对指纹。UDP 发现报文自身不是可信身份证明。发现受阻时可以输入 IP，但防火墙和 Wi-Fi 客户端隔离仍可能阻止连接。

连接后可直接选择大厅中的房间，或按房间号加入未列出的房间。密码为空的房间不需要邀请凭据。房主可选择规则、剧本、3／4 席、胜利分数和当前 AI 席位；所有人类准备后开始。更改配置后需重新准备。对局开始后新玩家不能抢占原席位，原玩家须用设备安全保存的凭据重连。

在线大厅使用相同客户端与协议，填写已部署服务的 HTTPS 地址，按系统信任链和域名正常验证证书。本次没有可提供的公共在线服务器；部署方式见 [服务端说明](M7_SERVER.md)。Windows 是本轮联机验证目标，现有安卓单人功能保留；安卓联机、安全凭据存储与发布后端未作为已验证交付。

## 权威与隐私

- `Catan.Network.Contracts` 为 .NET Standard 2.1 协议与显式类型 JSON 编解码，Unity 与服务共用。协议不接受任意类型名、未知字段、重复字段或非法枚举。
- `Catan.Rooms` 适配四种现有规则入口，规则核心和当前 AI 没有复制或修改。每房间顺序处理命令，以认证凭据确定席位，校验控制 ID、规则/场景版本、命令 ID 和预期修订号。
- `Catan.Server` 是纯 .NET 10 服务，通过 HTTPS/WSS 发送各席位的 `PlayerView`，历史按授权席位分页。客户端不实例化本地规则主机，不运行对手 AI，不导出服务器权威存档。
- Windows Unity 6000.3.25f1 / Mono 的实际局域网 WSS 握手未通过，日志为 `UNITYTLS_X509VERIFY_FLAG_NOT_TRUSTED`。客户端自动使用同一严格证书固定的 HTTPS 每秒同步，界面显示当前传输方式；命令与查询仍加密并认证，不关闭 TLS 校验。服务端 WSS 已由独立 .NET 客户端验证，不能据此声称 Unity WSS 通过。
- AI 在服务端只读取所属 `PlayerView`，通过同一规则 `Execute`。不同玩家的弃牌、交易、金矿、进步卡等待决按实际有权行动的席位调度。
- 命令重试先查持久账本，再检查修订号。同 ID 同内容返回原结果与最新本人视图，同 ID 不同内容拒绝。`CommittedRevision` 是原命令提交号，`Revision` 是回复时的当前局面。
- 网络快照最多保留 37 条真实公开事件：最近 32 条、最近回合边界、本回合各席最近一次报价。完整授权历史通过游标分批取得，每页最多 200 条。其他玩家的隐藏手牌、牌库顺序、未揭示地图、随机状态和命令原文账本不进入网络输出或公开日志；本人手牌及规则允许的临时查看信息只发给有权玩家。

局域网服务保管完整权威状态，因此玩家需要信任房主电脑所有者。客户端侧隐藏界面不能阻止房主读取自己电脑上的服务存档。此次沿用已有规则随机算法，不以隐藏种子替代密码学不可预测性保证。

## 保存与故障恢复

方案中的 SQLite 是建议选型。本轮采用完整房间文档的原子文件事务：规则快照、修订号、命令账本、设置、身份哈希及首次加入登记一同写入同目录临时文件，调用 `Flush(true)` 后以 `File.Replace` 提交；首次创建用同目录 `File.Move`。成功后才发送确认。服务目录与房间目录均有独占写锁。`IRoomStorage` 保留后续替换数据库的边界。

此调整减少 Windows 随包服务的数据库依赖，适用于当前单实例、每房间串行写入。每次提交会重写完整房间文档，成本随存档和账本增长；没有数据库查询、跨房间事务、多实例调度或自动备份能力。进程重启和注入的写入失败已有测试，突然断电、底层文件系统及磁盘缓存的持久性仍须在目标部署环境另验，不能从本机检查推导保证。

写入失败后恢复最后已保存状态并暂停房间，不能发布未提交局面。损坏或版本不兼容的存档保留原文件并拒绝启动，不用新局覆盖。所有人离线时暂停 AI，保留原席位与待决；局域网主机关机后，需要原电脑重新启动同一服务目录才能恢复。本期不自动传送存档换主，不自动代打断线人类。

密码使用随机盐及 100,000 次 PBKDF2-SHA256；访客凭据使用随机令牌，服务只保存 SHA-256 哈希。凭据默认有效期 180 天，是当前实现参数，可通过 `RoomDirectoryOptions.CredentialLifetime` 调整。大厅退出会释放席位并撤销该身份；开局后退出保留原凭据、席位和待决。显式 `Revoke` 永久吊销凭据，已经开始的席位继续等待，不能重新领取。

重连发放新的连接控制 ID，旧连接随后不能操作或读取该席位。房间管理权可以转交，也会在管理员掉线或心跳超时后交给在线人类；管理权变更不迁移权威存档，不改变任何玩家的隐藏信息权限。

Windows 客户端用当前用户 DPAPI 保存凭据。遗失、过期或吊销的凭据不能凭昵称或房间号找回；账号、跨设备身份恢复及人工找回尚未实现。请保留私有服务目录的受限备份，不放入分享包或 Git。

## 首次创建或加入的回执恢复

当前客户端在发送 `Create`／`Join` 前生成随机申请编号 `EnrollmentId` 和 32 字节随机恢复令牌 `EnrollmentCredential`，先将原申请和令牌写入本机 DPAPI 安全存储。第一次响应丢失时，重试保留这两项和完整原申请，不重新生成身份。

服务将申请编号、凭据哈希、申请内容指纹与房间及席位放在同一次持久提交内。内容指纹使用原恢复令牌为密钥计算 HMAC-SHA256，密钥本身不落盘；这避免将含房间密码的申请直接快速哈希后，产生额外的离线密码猜测校验值。

相同申请重试返回同一房间、当前所属席位及当前可见状态，不重复创建或占位；响应不再回传长期凭据。重复响应的 `CommittedRevision` 保留最初申请提交号，`Revision` 表示当前状态。相同编号或令牌用于不同内容会被拒绝；大厅退出、凭据过期或吊销后仍保留登记墓碑，不能通过重试复活失效身份。服务重启后的重复申请和首次写入失败后的重试均有独立测试。

协议仍兼容不带这两个字段的旧验证驱动，其首次响应由服务生成凭据。该兼容流程不具备首次响应丢失后的身份恢复能力，产品客户端使用预存申请流程。此机制只解决同一申请的恢复，不引入账号或跨设备找回。

当前默认限制为 128 个保留房间；每房间最多保存 100,000 次身份申请，人类与 AI 合计成功执行的规则命令也不得超过现有规则存档的 100,000 条恢复上限。达到上限时保留最后已提交局面并拒绝继续推进。限额是保护措施，尚无长期容量承诺。
