# 操作 UI v001

2026-10-11，本轮按用户提出的桌面布局重构 M6 的玩家操作区：下方集中展示手牌，上方排列可放置的组件与城市设施；支持从组件选择费用，也支持从资源手牌发现可建项目，并增加统一交易面板。

本次范围是可玩的操作界面迭代，没有修改规则版本或阶段退出条件，也不代表 M8 成品体验或用户外观验收已经完成。

## 启动与适用范围

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\development\Play-M6.ps1
```

需要重新构建时：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\development\Build-M6.ps1 -VerifyPlayer
```

场景为 `Unity/Catan/Assets/M6.unity`，Windows 程序为 `.local/m6/Builds/Windows/CatanM6.exe`。进入 M6 后，基础版、航海家、城市与骑士、双扩展组合四种模式均使用新操作区。通过 `Play-M2.ps1` 至 `Play-M5.ps1` 启动的独立本地换座版本继续保留各自旧 UI；它们不用于验收本轮新布局。

## 布局与建造

最下方左侧是发展卡或进步卡，右侧是资源牌；两区之间留有间隔，资源手牌在自己的区域内居中。城市与骑士和组合模式将商品与资源一起展示。手牌较多时可以在手牌区域内滚动查看。

地图与手牌之间，左侧排列本人剩余的道路、定居点、城市，以及当前规则使用的船、城墙和三级骑士；每种组件显示余量。右侧是贸易、政治、科学三项城市设施及当前等级。基础版和航海家明确提示没有城市设施。右侧操作栏保留掷骰、结束回合、目标和参数确认、弃牌及其他待决选择、特殊骑士或航海行动、公开分数、保存和恢复。

两条建造入口共享同一份选择状态：

1. 点击组件或设施，费用浮窗列出资源图标与数量，并自动将已经持有的对应资源牌向上抽出。所需资源齐全、当前阶段允许、库存与合法目标均满足时，才准备建造。
2. 直接点击资源手牌选择相应数量。所选资源覆盖费用的可建项目会高亮并上浮；可以有多个匹配项目，仍需点击想建的组件确定意图。

资源不足的组件仍可点击查看费用。已有资源保持正常色彩；缺少资源显示暗色图标、珊瑚红边框和减号，并写明缺少数量。查看费用、抽出手牌和取消选择均不扣费。点击缺资源项目不会进入棋盘放置。光标进入地图时，费用浮窗收起并保留当前选择，避免遮住低处的放置目标。

基础版和航海家沿用“拿起 → 棋盘预览 → 单击落下”的确认方式。城市与骑士及组合模式先选棋盘目标，再在右侧确认执行。最终操作仍通过各规则包既有的 `Submit` / 规则指令入口校验；动画与 UI 选择不决定规则结果。

开局组件显示零资源费用；基础版和航海家的免费道路 / 船阶段也使用免费组件槽。城市与骑士和组合模式的进步卡免费建设继续在右侧待决中逐步完成，不从普通付费组件槽进入。城市与骑士的第二轮开局建筑是城市；对应城市槽位用于免费开局放置。强力和精锐骑士槽位表示将低一级己方骑士晋升，不能直接招募高级骑士；棋盘预览、目标点击与确认均保留等级限制。激活、移动、驱离和驱逐行动仍在右侧操作栏完成。

点击城市设施后会锁定该次草稿的设施轨道，右侧确认不会切换到另一轨道；改选其他设施应点击对应设施槽。改良费用、城市条件、大都会争夺和后续待决仍由规则核心处理。被劫掠城市的修复继续遵循原规则，包括没有闲置城市棋子时使用原棋子的修复情况。

`Esc`、右键或“清空选择”取消当前草稿。提交、恢复局面、席位变化及新的玩家视图会清除过期选择。手牌、费用浮窗、卡牌预览、交易弹窗和侧栏会拦截棋盘操作；在这些区域滚动不会缩放棋盘。

## 发展卡与进步卡

点击左侧卡牌先阅读说明。选择“使用 · 选择目标”只准备出牌，再通过右侧参数与确认流程执行，避免阅读卡面时直接消耗卡牌。

基础版和航海家保留骑士、道路建设、丰收、垄断及隐藏胜利点的规则差异。本回合买入的行动发展卡不可立即打出；丰收与垄断在右侧选资源后确认。购买发展卡也先选择费用，再确认购买。基础发展卡实物照片尚缺，使用文字卡面。

城市与骑士和组合模式使用已有进步卡照片卡面，并保留各卡的目标、掷骰选择、对手选择以及后续待决流程。仅展示本人有权查看的卡；临时允许查看的对手卡仍由原有待决面板按权限显示。

## 交易

点击底部右侧“交易”，打开交换盘。交易仅在规则允许本人发起的行动阶段开放，未完成的待决或已有报价会阻止新交易。

| 方式 | 操作 | 确认后的行为 |
| --- | --- | --- |
| 银行 / 港口 | 选择付出种类、获得种类与交换份数；查看当前最优比例及银行库存 | 一次交换一种付出与一种获得；比例按港口及当前扩展能力计算，确认后提交银行交易指令 |
| 与玩家交易 | 选择对手，在“我付出”和“我获得”两侧配置各资源及商品数量 | 发送公开报价，等待对方接受或拒绝；接受时由规则核心再次校验双方实际持有量 |
| 收到报价 | 阅读双方交换内容，选择接受或拒绝 | 只有收件人拥有响应权限；不会展示对方完整手牌 |
| 撤回报价 | 发起方点击撤回 | 可以撤回自己的未完成报价，即使当前调度正在等待收件人响应 |

空报价、负数、超过本人持有量、同一种资源同时付出和获得、错误银行比例或银行库存不足，会阻止草稿提交或被规则入口拒绝。关闭交换盘只取消本地草稿；已发出的报价通过“撤回报价”取消。拒绝或撤回不交换资源。

## 图标与素材来源

来源清单、UV 取样矩形、文件哈希与复现说明保存在 [操作区素材配方](../art/recipes/ui-operation-v001/README.md)及 [sources.json](../art/recipes/ui-operation-v001/sources.json)。照片只提供外观参考，费用与权限来自规则数据。

- 布匹、钱币、纸张图标取自一级市场、市政厅、修道院卡的费用面，使用其中的单个商品符号。
- 当前仍缺基础版建造费用卡照片。因此木、砖、羊、麦、矿图标取自已有资源手牌插画，不能称为费用卡裁片。木头使用此前保留的 AI 清理样板；另外四种使用原照片几何校正资产。
- 八种资源与商品图标使用已有纹理的 UV 区域，不重写原始照片或卡面。
- 组件槽使用 32 张透明缩略图：四个玩家颜色 × 道路、定居点、城市、船、城墙、三级骑士。它们从保留的实际网格源文件固定相机渲染，并非新增 3D 模型或 AI 生成图。来源、导出和校验见 [缩略图清单](../art/exports/ui-operation-v001/pieces/manifest.json)与 [校验记录](../art/exports/ui-operation-v001/pieces/verification.json)。

派生资源位于版本化路径 `art/exports/ui-operation-v001/pieces` 和 `Unity/Catan/Assets/Resources/OperationUI/v001/pieces`；原始照片、既有 `.blend` 与其他版本导出继续保留。

本轮真实鼠标建造、交易和出牌操作未能可靠确认：其他用户窗口抢占前台，无法把点击与游戏内结果稳定对应。因此这里只记录实际窗口人工视觉检查，不声称完成了真实鼠标交互验收。

## 待用户试玩与边界

尚待用户确认手牌密度、组件辨识、费用提示和交易步骤是否顺手，并完成实际整局试玩。较小窗口、不同分辨率及所有长待决参数面板没有逐一人工验收；建议先最大化窗口。四种模式的集成检查不替代每张进步卡和每个剧本特殊动作的本轮鼠标复验。

基础费用卡和基础发展卡照片的缺口仍保留；现有照片的反光、清晰度以及木头样板的 AI 清理限制也未被本轮 UI 改动消除。最终美术、实测尺寸、长期性能、M7 联机与 M8 发布验收仍按现有路线图分别推进。
