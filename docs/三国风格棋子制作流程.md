# 三国风格棋子制作流程

日期：2026年10月22日。适用项目：《卡坦岛之三国争霸》。文档状态：制作流程；造型、尺寸和预算仍按样板逐项确认。

## 一、目标与使用范围

制作可在 Unity 游戏中360度观察、稳定摆放、清楚识别且能重复生成的三国风格三维棋子，覆盖 Windows 与 Android。

本流程用于现有棋盘组件的三国化制作。项目当前搁置 Ultra，本流程作为独立美术工作规范使用，不以恢复 Ultra 地形、环境动态或双主题升级为前提。

依据：

- [项目简报](PROJECT_BRIEF.md)、[开发路线](ROADMAP.md)与[美术生产规范](ART_PIPELINE.md)。
- [三国棋子概念图 v001](../art/concepts/three-kingdoms-pieces-v001/说明.md)及[原始生成提示词](../art/concepts/three-kingdoms-pieces-v001/生成提示词.md)。四张概念板目前是待审阅的造型提案，不能直接视为已确认成品。
- [美术转化清单](ART_CONVERSION_CHECKLIST.md)。旧[逐棋子覆盖表](verification/ultra/U0-piece-coverage.md)可帮助查漏，实际资产入口和状态以当前工程重新核对为准。
- 涉及三国扩展状态时，查阅[三国争霸游戏百科](三国争霸游戏百科.md)及[扩展实现方案](三国争霸扩展实现方案.md)。未裁定的规则不能由美术制作补成规则。

本流程的“棋子”包括建筑、道路、兵卒造型的骑士、船只、中立人物和剧本标记。54张武将牌属于独立牌面范围，不自动变为54个棋盘人物模型。名将雕像如另有需求，单独建立任务。

## 二、统一造型语言

### 1. 视觉方向

采用汉末三国题材启发的收藏级微缩棋子：轮廓清楚、比例适度概括、材质细腻、轻微手涂感。此为美术设计方向，不宣称考古复原；需要历史依据的具体形制另查可靠资料并记录出处。

- 建筑：灰陶瓦、深木梁柱、夯土与灰石、少量朱红漆；构图紧凑，屋顶和门楼形成主要轮廓。
- 人物：布衣、札甲、皮革、旧铜或暗铁；适当加粗手脚、兵器与连接处，脸部保留大形体。
- 船只：深浅木板、米麻色帆、简化绳索和护舷；船首、船尾与帆形清楚。
- 标记：深木与旧铜，浅浮雕图案简洁，缩小后仍能辨认。
- 全系列统一倒角尺度、磨损程度、底座厚度与光照基准，避免单件过度华丽。

不使用日式城堡、西欧板甲、明清宫殿式金顶或夸张魔法装饰作为默认设计。概念图中的旗字、碑文和数字不作为最终规则信息，准确文字和数值由结构化数据制作。

### 2. 四席归属与状态

沿用朱红、靛蓝、赭橙、米白四席配色，具体色值从当前工程读取。底座色带、旗帜或局部布料承担归属信息，主材质保持统一。玩家颜色与行动次序、魏蜀吴等势力不自动绑定。

归属、等级和当前状态分别表达：

- 归属：玩家色，并保留选中时可读取的所属玩家信息。
- 等级：轮廓、装备和一至三个明确等级标记，不能只靠颜色深浅。
- 待命／激活：同一人物的收兵／戒备姿态或独立状态件，配合现有界面提示；不只靠发光表达。
- 选中、合法预览、非法预览：作为交互表现叠加，不能抹去归属和等级。

默认游戏距离下先读懂棋子种类，再读归属与状态，最后观察装饰细节。

## 三、建立棋子清单与制作顺序

以下是依据现有概念板整理的造型候选，不修改程序名称、规则身份或效果。

| 原有棋子或组件         | 三国造型方向                     | 必须覆盖的区别与组合                         |
| ---------------------- | -------------------------------- | -------------------------------------------- |
| 道路                   | 低矮石土驿道                     | 四色、边方向、转角相接；两端净空             |
| 村庄                   | 里邑、小型灰瓦院落               | 四色，与城市轮廓明显不同                     |
| 城市                   | 郡城、门楼与院落                 | 四色，有墙／无墙                             |
| 独立城墙               | 低矮城垣模块                     | 能装配城市和三类大都会；区别于装饰院墙       |
| 三类大都会             | 商都、学宫、王城                 | 贸易／科学／政治身份，各自四色和有墙／无墙   |
| 骑士                   | 三级汉军步战武人                 | 三个等级×待命／激活×四色，共24种状态组合   |
| 玩家船、战舰           | 商舸与蒙冲造型                   | 四色，普通／战舰，同一水线占地               |
| 强盗、商人             | 山寇、行商                       | 两个独立中立身份，区别于玩家兵卒             |
| 海盗、蛮族入侵船       | 江盗船、寇军楼船                 | 海域棋子与轨道棋子的尺度、锚点分别确定       |
| 海盗要塞、中立村庄     | 水寨、织乡                       | 已有强度、数量及剧本状态单列                 |
| 五类奇观               | 长垣、津梁、功业碑、乐舞台、楼阁 | 与当前五类奇观稳定身份一一映射，等级独立展示 |
| 港口、布匹、分数等标记 | 令牌、卷帛筹、旧铜牌             | 类别、数量及准确图标；按实际剧本补齐遗漏项   |

每项登记：稳定资产 ID、规则身份、参考文件、确认状态、颜色、等级、状态、组合件、预计同屏数量、占地、最高点、枢轴、LOD、材质、贴图、使用入口和验收状态。

相同模型的24种状态组合不要求24套独立网格。优先复用几何、材质和状态部件，逐组合验证显示正确。

建议制作顺序：

1. **第一组样板：村庄、城市和独立城墙。** 锁定材质、四席配色、占地和可组合结构。
2. **第二组样板：一级兵卒待命／激活。** 锁定人物比例、武器净空、等级与状态表达。
3. **第三组样板：玩家船和战舰。** 锁定水线、朝向、桅杆高度和升级识别。
4. 样板确认后，扩展道路、三类大都会、其余兵卒等级及公共棋子。
5. 最后补齐奇观、剧本标记和已确定的特殊状态。

每组先完成概念到游戏的完整闭环，再扩大同类制作。

## 四、阶段一：分析参考并确定规格

### 输入

本轮指定棋子的概念图、原实体参考（如有）、当前游戏对应模型与摆放位置。

### 操作

1. 标出必须保留的外轮廓、主体比例、材质分区和身份特征。
2. 将参考中不可见的背面、底部、内部记录为“设计推定”；概念图的陈列大小不作为尺寸依据。
3. 从当前工程读取交点和边的可用空间、棋盘基准面、镜头缩放、供应区及预览尺寸。缺失值标为估算。
4. 建立侧向与高度包围范围，预留相邻道路、建筑、兵器、船帆与数字标记的净空。
5. 将棋子拆为必要组件。例如：城市拆为主体、屋顶、门楼、归属装饰；城墙作为独立装配模块；兵卒拆为人体、装备、武器、状态件和底座。
6. 明确主体是否需要骨骼或动作。静态状态切换可使用姿态网格或状态件，不默认增加持续动画系统。

### 输出与通过条件

输出单件规格表、组件清单和尺寸草图。规则身份、必须覆盖的状态、占地和参考的不确定部分均有记录，才进入详细制作。

## 五、阶段二：独立提取图与辅助多视图

从概念板提取完整单件，补全合理的背面与被遮挡结构。需要的视图为原角度、正交正视、正交右侧、正交顶视；背面结构复杂时补正交背视。

每条实际提交给 ImageGen 的提示词都必须独立完整，写明参考文件、对象、固定特征、颜色、状态、视角、背景、光照和排除内容，不使用“同上”。调用工具前阅读 ImageGen Skill。

下列模板中的方括号由执行者根据规格表填入。提交时去除占位符，展开所需固定特征与完整约束。

### 模板 A：原角度完整单件

```text
根据提供的参考图【文件及对象所在位置】，提取《卡坦岛之三国争霸》的【棋子名称】，仅输出这一件棋子及其必要底座。
采用汉末三国题材启发的收藏级微缩模型风格，保持参考中的【轮廓、结构数量、比例、装备、材质和归属色详细描述】。当前等级与状态为【明确填写】。
沿用参考中该对象的观察方向。补全被遮挡的底部、背部连接和承重部件，使主体完整、稳定接地；补全只延续已有结构逻辑，不新增大型装饰或其他棋子。
材质细腻克制，灰瓦、深木、石土、旧铜、布料或札甲按本对象的实际需要使用，保持小尺度微缩质感。
背景为纯暗紫色，无渐变、无场景、无地平线；中性柔光，不用强阴影掩盖结构。完整呈现物件，不裁切，不加标题、水印、说明文字或规则数字。
这是一张建模参考图，图中不得附加地形、额外人物、城市背景或其他状态版本。
```

### 模板 B：单张正交视图

```text
依据提供的原始参考图【文件】及已确认单件提取图【文件】，绘制《卡坦岛之三国争霸》的【棋子名称】的【正交正视／正交右侧／正交顶视／正交背视，提交时只保留一种】。
保持【结构数量、主体比例、装备、归属色、等级、激活状态和材质分区的完整描述】。汉末三国题材启发的收藏级微缩风格，细腻、克制，与输入对象一致。
必须使用严格正交投影，不使用透视、等轴测或三分之四视角。相机沿【在规格表定义的观察轴线】观察，与对应基准平面垂直；画面不旋转、不倾斜，平行结构无近大远小和消失点。
正视或侧视不得露出因俯仰相机产生的顶面；顶视必须垂直向下，不得露出由斜俯视造成的竖直底座侧壁。物体本身斜面按正确投影保留。
物件朝向和尺度以规格表为准；保持整体比例，不为填满画布而拉伸。主体完整、不裁切。不可见部分按已有结构合理补全，不改变构件数量、不新增装饰。
纯暗紫色背景，无场景和地平线；中性柔光，无强投影、文字、水印和其他对象。
```

### 检查

- 各视图的屋顶层数、门窗、兵器、帆桅及底座结构相同。
- 右侧与左侧不混淆，人物姿态、持物手及船首朝向一致。
- 无悬空、融化、重复部件、裁切或背景物混入主体。
- 尺寸或结构相互矛盾时记录修正，不能把多张生成图都认定为精确事实。

生成图只作为辅助设定。后续使用同一个 Blender 模型渲染真正的正交视图，作为统一结构基准。简单道路、底座和标记可直接以灰模完成设定，无须机械生成全套图片。

## 六、阶段三：灰模与真实建模

### 1. 灰模先通过占地验证

以米制制作，记录对应实物毫米尺寸；Unity 按项目约定核对单位、缩放和轴向。建筑及人物枢轴设在底面中心，道路设在长度中点，船记录水线和统一船首方向。

只用主体体块建立城市、屋顶、人物、兵器或船体，先导入游戏检查：

- 村庄、城市、三种大都会在实际镜头下容易区分。
- 城市与大都会装入同一城墙接口，内外表面无重合和明显穿插。
- 道路端部、武器、旗杆和船帆不侵入相邻棋子必要空间。
- 城市自带院墙不被误认成有规则效果的独立城墙。
- 地形起伏下稳定落位，不依赖碰撞或动画确定规则位置。

### 2. 逐组件细化

先还原大轮廓，再加屋檐、梁柱、护甲、护舷等中等结构，最后加入小尺度纹理。建筑、武器和底座的可见硬边适度倒角。

布线服务于轮廓与变形。需动画的关节保留合理环线，避免细长退化三角形和无意义细分。静态资产允许合理三角化，最终以导出结果核算面数。

人物衣摆、披风、手与武器之间要有可读的连接关系；武器适度加粗和收拢，不以超长兵器表现等级。船底、水线附近和背面保持完整；帆与薄片的双面或厚度方案在 Unity 中检查。

门窗能看入的范围制作真实厚度和必要内侧结构，封闭区域无需完整室内。所有可观察方向无明显破洞、反面消失、悬空、穿模或重合面闪烁。

### 3. 状态与装配

底座、玩家色区域、城墙、轨道身份徽记与激活状态件分工明确，按需要共享网格与材质。休眠和激活保持同一等级的装备身份；城市升级为大都会后仍能装配城墙。

三国扩展涉及实际等级与有效等级、控制权与所有权、损毁与修复等区别时，依据已确认公开状态展示。临时加成优先使用准确状态标记，不能擅自创造新的常驻兵种或把控制者颜色覆盖为所有者颜色。

尚未定案的损毁／修复表现单列待定，不提前把所有受损建筑统一替换成废墟。动画和状态件只影响表现，不参与指令合法性与规则结算。

## 七、阶段四：UV、材质与性能预算

### 1. 材质制作

同类木材、瓦片、金属和布料共享材质库。小棋子首先保证色块与材质差异，避免密集划痕和高频细纹造成缩小闪烁。

UV 按模型尺寸和预计屏幕大小统一纹理密度；接缝放在隐蔽处，检查拉伸、图集边缘及远距离采样。基础色不画死场景阴影和镜面高光。法线优先从高模或经验证的高度信息烘焙，检查 Unity 的方向和强度。

需要生图时仅生成适合 UV 的材质候选；不能把有透视和投影的整件参考图直接投到模型所有表面。纹理空间、金属／粗糙程度与项目 URP 材质通道对应关系以实际着色器核对。

旗字、数字、等级和资源符号用准确图形或排版制作。中立身份和玩家色在暖光、阴影、选中高亮及远景中都要清楚。

### 2. 起始预算建议

下表用于首轮样板规划，不是已验证的性能承诺。按当前棋盘最大同屏数量和设备测量调整。

| 资产类别                     | LOD0 候选三角形数 | 细节安排                       |
| ---------------------------- | ----------------- | ------------------------------ |
| 道路、薄标记、简单筹码       | 100–600          | 轮廓与浮雕优先，细纹用贴图     |
| 村庄、独立城墙、普通船       | 800–2500         | 保留屋檐、墙厚和船首轮廓       |
| 城市、大都会、复杂船只、奇观 | 2000–6000        | 先满足游戏镜头下的体块与身份   |
| 兵卒、强盗、商人             | 1500–5000        | 轮廓、装备与姿态优先，面部概括 |

组合件分别记账，同时统计“城市＋城墙＋装饰”等一个可见实例的实际总数。不能把每个子物体都控制在6000面后就声称整个棋子满足预算。

按需要提供 LOD1／LOD2，起始可尝试约 LOD0 的50%／25%，以轮廓、状态标记和实际切换观感决定是否采用。简单资产不强制增加 LOD。贴图先评估共享图集和512／1024级资源，只有近景确有收益时才提高。

同时记录材质数量、绘制调用、透明叠加、阴影、纹理内存和同屏实例数。棋子透明预览与正式模型分别测试；不能仅看面数判断性能。

## 八、阶段五：导出、接入与验收

### 1. 导出与回读

保留源 .blend、制作脚本、种子和参数。沿用项目已经验证的显式导出路径，将模型与纹理分开保存；重新导入导出文件，核对缩放、轴向、法线、材质、UV、三角形数、状态部件与依赖纹理。

渲染对象与拾取碰撞分离，碰撞使用简化形体。所有规则位置绑定稳定 Tile／Vertex／Edge ID，摇晃或拿取动画只改变视觉节点，不改变规则锚点。

### 2. 所有使用入口覆盖

逐件检查棋盘正式模型、供应区、建造预览、合法／非法目标提示、缩略图、升级替换、移动和拿起／落下动画。存在组合状态时预览必须匹配最终组合，不能以普通城市预览冒充带墙大都会。

材质或模型的选择只使用当前玩家允许看到的信息。未登场、暗置或未知状态使用合适的通用显示，不能通过模型、缩略图或加载占位泄露隐藏内容。

### 3. 视觉与交互检查

- 同一真实模型渲染正交正面、右侧、顶面、背面及参考角度。
- 在 Unity 输出默认游戏镜头、近景、反向镜头与拥挤节点截图。
- 逐项检查四色、兵卒六态、三轨大都会及有墙／无墙组合；普通船与战舰在同一位置对照。
- 检查顶视识别、归属色、相邻遮挡、点击与触控目标、升级和移动后的落点。
- 分别标明概念图、Blender 棚拍和 Unity 实际运行截图，不相互替代验收。
- 在最大测试局面测量真实帧时间和内存。Android 无真机结果时保持待验，不根据桌面数据宣称通过。
