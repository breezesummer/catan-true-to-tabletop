# M5 双扩展组合架构

规则位于纯 C# 的 `Catan.Core.M5`，以 .NET Standard 2.1、C# 9 为兼容面。M2、M3、M4 的命名空间、存档格式和启动入口保留；M5 使用独立规则版本 `catan-seafarers-cities-knights-2025-en-v1`、场景版本 `m5-combined-official-2025-v001`、保存格式 `5`。

```csharp
var game = CombinedGameSession.Create("heading-for-new-shores", 4, seed);
var preview = game.Preview(command);
var result = game.Execute(command);
var seat = game.GetPlayerView("P1");
var restored = CombinedGameSession.Load(game.Save());
```

## 组合边界

`CombinedScenarios` 只接受[兼容表](M5_SCENARIOS.md)中的两个剧本。地图构造复用 M3 已核对的固定图、港口、起始区域和奖励区域，保留 Tile、Vertex、Edge ID；组合规则与状态在 M5 内实现，避免改变已交付单扩展存档的解释。采用具体组合实现，没有加入通用插件系统。

城市骑士的商品、改良、蛮族、骑士、进步卡、城墙和大都会，与航海家的船、海盗、金矿和异乡定居奖励共用一个权威状态及命令入口。Unity、本地验收席位和后续网络适配器均调用 `Execute`；动画、碰撞和渲染不参与规则裁决。预览只修改事务副本，拒绝命令不改变状态；成功命令按 ID 与输入指纹去重。

组合地图的合法目标较多。`M5Transactions.cs` 直接复制所有可变状态分支，避免每次目标预览都往返序列化；只有引擎内部只追加的既有事件与命令回执共享。独立案例比较复制前后序列化值，并检查嵌套引用隔离、失败晋升回滚、号码交换预览与待决骑士/金矿预览，防止性能调整破坏权威状态。

## 三种路线判断

- 骑士可达性：沿己方道路及船遍历，可在没有建筑的顶点转换陆海路线，敌方建筑和骑士阻断继续前进。
- 最长航线：道路与船只有在己方建筑处才能连算，骑士不能代替建筑完成接续；敌方骑士截断路线。
- 船是否开放：己方建筑和骑士可封闭船线。敌方骑士造成的最长航线中断不能使相邻船变得可移动；普通移动还检查船龄、当回合移动次数、海盗和骑士连接。

这三种判断分别实现。Diplomacy 的开放船移除允许海盗旁的例外，但必须按原类型补建。Road Building 允许道路与船混合完成两次免费建造。

## 顺序、待决与权限

沿用 M4 的事件先于产出顺序。首次蛮族攻击使强盗规则生效；海盗在首次攻击结算完成后进入剧本初始位置。全地图城市和激活骑士参加同一次攻击。进步卡、蛮族劫掠或并列防守奖励的待决完成后，才继续本次产出或七点流程。

金矿使用显式待决，城市两张、村一张，只能领取资源。金矿受益者已经获得本次产出资格，不能再领取水渠补偿；金矿选择完成后继续剩余队列。免费船、骑士撤退、逐人进步卡选择等都由有权席位提交命令。

`PlayerView` 通常只含本人手牌和公开棋盘、数量、得分、组件供应及合法动作。对手资源与商品通常只显示合计数量；仅在 Espionage / Guild Dues 等规则授权的窥看待决中，向指定席位额外投影相应对手信息。进步卡牌库、随机状态及完整成功命令历史属于本地权威数据。公开事件不记录抽牌、偷牌、弃牌或自选资源的组成。换座和载入先清空私有视图与未完成的界面选择，确认席位后重新投影。

## 保存与验证

保存包含规则版本、场景内容指纹、种子与随机继续状态、资源和商品供应、船龄与移动标记、骑士状态、进步牌库、异乡奖励、待决队列及成功命令账本。生产 `Load` 从相同场景与种子重放成功命令，比较完整权威结果；拒绝不支持的版本、剧本或篡改内容，不接受测试夹具作为正常存档。

独立固定案例覆盖组合条款、非法操作原子性、供应守恒和权限边界。四个正常完整局仅用各席位 PlayerView 决策，经过生产命令入口；测试策略不是 M6 产品 AI。Unity 与独立 Windows 的实际结果单独登记在 [M5 验收记录](M5_ACCEPTANCE.md)，不以 .NET 测试代替。

## 表现资源

M5 复用 M1 地形样板和 M3/M4 可辨识网格占位，在组合棋盘上同时显示船、海盗、骑士、城墙、大都会和商人。估算比例、枢轴与可复现代码按 `art/recipes/m5-v001/` 登记。它们是实际网格，未声称为用户已确认的收藏版成品美术。
