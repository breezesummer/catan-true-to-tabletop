# M4 城市与骑士架构

M4 使用纯 C# `Catan.Core.M4`，保持 .NET Standard 2.1 兼容面。M1、M2、M3 的命名空间、存档和启动入口分别保留。M4 规则版本为 `catan-cities-knights-2025-en-v1`，场景版本为 `m4-random-board-v001`，存档格式为 `4`。原有基础格、点、边 ID 继续作为棋盘定位依据。

```csharp
var game = CitiesKnightsGameSession.Create(topologyJson, 4, seed);
var preview = game.Preview(command);
var result = game.Execute(command);
var player = game.GetPlayerView("P1");
var restored = CitiesKnightsGameSession.Load(topologyJson, game.Save());
```

## 规则边界

UI、本地测试席位和未来适配器均通过 `Command` / `Execute` 执行操作。规则不依赖 Unity、碰撞、相机、动画或网络。操作先应用于事务副本；只有校验和不变量检查成功，才替换权威状态。命令 ID 配合完整输入指纹，重复输入只返回原回执，同 ID 改内容拒绝。

M4 从基础棋盘开始，不带入航海家船、海盗、金矿和剧本奖励。基础发展卡与最大军队在城市与骑士中不启用。商品保持独立类型，避免将纸、布、币错当资源专用港或水渠可选资源。

## 事件和待决

蛇形开局依次放一村一路、一城一路；城市开局只领取单份资源。正常回合以事件骰结算为先：进步卡发放及手牌超限、蛮族攻击及城市降级或并列防守选牌，必须完成后才执行本次骰点产出或七点弃牌。首次攻击也负责启用强盗。奖励或劫掠选择后，自动队列项 `BarbarianReturnHome` 才将船归起点、停用骑士，然后继续生产；若此前取得第 13 分则立即终局。

待决应保存操作者、效果类型、剩余对象队列、选择数量、返回阶段，以及之后尚未执行的产出。卡牌涉及他人选择时交给该席位操作，不能由出牌者代替选牌。移动和驱逐骑士根据己方道路图遍历；对手棋子阻断路径，不使用 3D 距离判断。

骑士保存等级、活跃状态、当回合激活和晋升标记。大都会按轨道独占，城市和城墙按顶点绑定。没有村棋子时的毁城保存为特殊降级状态，仍占用原城市棋子，并限制后续城市升级顺序。贸易船队和商业港口属于当回合效果，跨回合失效。

## 信息权限

权威状态和保存文件包含资源与商品手牌、进步牌手牌与牌库顺序、随机继续状态及私密命令账本，仅供本地权威与测试断言。`PlayerView` 只给出本席位的完整手牌；对手仅显示资源与商品合计手牌数、分数、改良轨道、棋盘骑士及供应等公开内容。兼容字段 `ResourceCount` 在 M4 表示这项合计，`CommodityCount` 不投影对手商品数量。

行会税和谍报的授权查看是临时能力：只有当前待决被授权的玩家能查看对应目标内容，其他席位不能获取；完成、取消换座展示或载入后不得遗留上一人的私有展示。公开事件只描述发生的操作，不记录抽牌身份、偷牌内容、弃牌组成或查看结果。

客户端在换座时清除旧私有视图并遮蔽手牌，确认后才投影新席位；载入也须重新遮蔽。测试席位的决策入口只接收 `PlayerView`，不接收会话、权威状态、存档或随机状态。该测试策略不构成 M6 正式 AI 产品。

## 保存和验证

保存必须包括规则/场景版本、来源场景指纹、初始随机种子与随机继续状态、全部组件及有限供应、待决队列、回合效果和成功命令历史。生产载入重新创建相同场景并重放命令，然后比较序列化权威结果，拒绝版本错误、内容篡改和未经正常操作的测试夹具。

独立固定局面负责条款及全部卡牌效果边界；非法命令比较前后保存；不变量覆盖资源 19/种、商品 12/种、三类进步牌各 18 和棋子供应。正常 3/4 人完整局负责流程活性和真实可重放待决。具体运行结果仅以 [M4 验收记录](M4_ACCEPTANCE.md) 的实际记录为准，不能以 .NET 测试替代 Unity 兼容性或用户本人试玩。

界面与实际网格占位的参数、来源、比例和复现方式另随客户端实现登记；本阶段不以占位模型替代收藏版成品美术确认。
