# 仓库与美术文件保存规则

2026-10-13 整理既有未提交文件，原始参考不删除、不重编码。本轮不改写历史提交。

- 提交游戏源码、测试、工具、Unity 场景和 `.meta`、Unity 正式使用的模型和纹理、文档及验收证据。
- 提交 `assets/references` 原始照片、原文件名备份和来源清单。归档照片与原名备份虽然路径不同，但相同字节在 Git 中共享对象。
- 提交 `art/recipes` 配方、生成与校验脚本，以及 `art/source` 必需源贴图。图片生成候选和概念图无法仅靠随机种子逐字节重建，因此仍保存。
- `entity-conversion-v*` 与 `photo-samples-v*` 的 `.blend`、中间 FBX、导出纹理副本和预览场景图可由配方重建，加入忽略。本地原文件保留；曾进入索引的这类文件仅解除跟踪。
- 上述导出的清单、来源、哈希和验证 JSON 仍跟踪；正式 Unity 资产不受忽略规则影响。原有手工/独立山地样板源文件仍跟踪。
- Unity 缓存、独立构建、权威试玩存档、临时日志及开发环境继续放在忽略的 `.local`；公开证据不得包含其他玩家完整手牌、牌库顺序或随机状态。

重建入口为 `tools/art/Build-PhotoSamples.ps1`、`Build-EntityAssets.ps1`、`Build-PlayerComponents.ps1` 和各版本配方中的说明。Unity 可直接使用仓库内的正式资产；只有重新生产素材才需要这些中间输出。
