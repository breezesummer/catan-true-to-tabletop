## 身份、隐私及故障检查

房间检查覆盖了身份与席位绑定、伪造玩家 ID、错误或过期凭据、规则及场景版本不匹配、旧连接被替换、管理员离线转交，以及最后一名大厅玩家离开后的空房间恢复。开局后掉线人类保留原席位并等待；全员离线时暂停 AI，原主机服务恢复后再继续。

首次创建或加入使用预存 `EnrollmentId` 和高熵 `EnrollmentCredential`。测试包含创建／加入回执丢失、服务重启、同申请重复提交、同标识不同内容冲突、首次保存失败重试、加入后换座、错误房间及大厅离开／过期／吊销后不得复活身份。服务只保存凭据哈希及用恢复令牌作密钥的 HMAC 内容指纹，不将含密码申请做无密钥快速哈希；旧验证驱动兼容入口没有首次回执恢复能力。

命令先认证并查持久去重账本，再判断修订号。同 ID、同席位、同内容只提交一次；不同内容拒绝。并发请求、回执重试、写入失败、重启后的待决和命令结果均有案例。保存失败回滚到最后提交状态并暂停，不公开未提交局面；损坏或不兼容存档拒绝恢复且不覆盖原文件。

网络编码根类型为明确白名单，拒绝任意类型注入、未知／重复字段及非法枚举。测试审查四规则本人视图往返及授权历史，权威存档不能通过公共编码入口传输。客户端快照仅含真实有权事件并有长度上限，服务端 AI 仍读取完整的自身 `PlayerView`。这些检查不等于已经完成面向互联网的第三方安全审计。

SQLite 建议被单房间原子文件提交取代，规则存档、修订号、命令账本和身份登记在同一文档提交；同目录临时文件 `Flush(true)` 后原子替换，目录独占锁约束唯一写入者。已有进程重启与注入写入失败测试，尚未执行断电、磁盘损坏或多种文件系统的持久性试验。每次重写完整文档，长时间运行和大账本性能也尚未验证。实现细节及使用方式见 [M7 实施说明](M7_IMPLEMENTATION.md) 与 [服务端说明](M7_SERVER.md)。

## 失败定位、修复及剩余边界

首轮 Unity HTTPS 证书回调接收到相对 URI，读取完整主机名时异常；修复为绑定该客户端固定端点解析 URI，继续严格验证证书指纹与地址。随后实际发现 Unity Mono 的 WSS 自签证书握手失败，HTTPS 回执又可能把连接状态设为成功，造成没有持续同步。现将推送连接状态独立管理，无 WSS 时每秒用同一 HTTPS 客户端同步，正常退出、断连和旧连接接管均受会话代数保护。四规则最终复验均推进至第 3 回合且所有权限断言通过。

早期超时报告的 Stage 是前一条已通过断言留下的标签，不代表权威主机断言失败；`OwnSeatOnly=false` 是未运行到最终断言的默认值。当时服务已向人类发出交易报价，正在等待回应。未把该失败样本计入成功。后台隐藏窗口的截图实际为黑色，不能作为外观或鼠标交互通过的证据。

服务重启探针还暴露了测试断言过严：管理员离线转交可以在重连与重复命令之间增加房间修订号，而规则局面和原命令提交号不变。正确验收应分别核对当前修订号不倒退、本人规则局面一致及原 `CommittedRevision`，不能要求两次独立回复的房间修订号恒等。
