# 美术生产规范

目标是以用户提供的实体道具为参考，制作可在游戏中旋转观察、稳定摆放和重复生成的收藏版资产。照片、扫描件、现成模型与规则页分别登记用途，原件只读保存，处理结果另存版本。

第一批只采集能够验证生产路线的样本：

M0 收口决定（2026-10-08）：用户允许实体参考后补，先使用明确标注的估算尺寸。当前估算参数与后补清单见 [REFERENCE_BASELINE.md](REFERENCE_BASELINE.md) 和 [v001 参数](../art/recipes/v001/scale-estimates.json)。这些参数不代表实测或正式样板验收；以下采集要求保留，收到资料后按新版本修订。

| 样本 | 建议拍摄或提供内容 | 用途 |
| --- | --- | --- |
| 版本与全桌布局 | 盒子或规则书的版本信息、完整桌面照片 | 确定版本、比例、公共与个人区域 |
| 山地、森林、海洋 | 各一块的顶视及约 45 度照片；至少一张带尺 | 检查最高遮挡、细碎景观和海岸 |
| 道路、船、城市、城墙、骑士 | 成排顶视、侧视、45 度照片；至少一件的长宽高 | 棋子形状、尺寸、枢轴与状态标记 |
| 资源卡与进步卡 | 各一张正反面，四角完整、平整、无反光 | 校验卡面比例、排版和材质 |
| 城市建设板 | 正视或平整顶视照片 | 确定扩展个人区域布局 |

固定光照和白平衡；比例尺与物体处于相同平面。照片不能提供的背面、底面和尺寸标为未知，不能自动当作已还原。若已有 .blend、.fbx、.glb 等模型，保留原始单位、贴图和来源说明。

生产步骤：

1. 登记参考编号、实测尺寸、用途和必须保留的特征。
2. AI 编写 Blender 脚本生成灰模，验证地块拼接、棋子占地和操作空间。
3. 使用固定随机种子生成山体、树林、田野和海岸；边与交点设为景观禁布区。
4. 用参数化几何、曲线与倒角制作棋子；复杂雕塑先完成轮廓清楚的样板，再逐步细化。
5. 制作程序化材质或纹理候选，必要时烘焙，统一导出模型和贴图。
6. 在 Unity 的正式相机和灯光下检查；确认一套样板后批量生成同风格资产。

图片生成可用于风格探索、卡面插画和贴图候选，生成图片本身不是可导入的 3D 网格。游戏模型还需要几何、UV、材质和导出。外部图转 3D 工具可另行评估，基础生产路线应能用本地 Blender 脚本继续推进。

卡牌规则文字、费用、数字与图标由结构化数据和排版组件确定；图像模型生成的文字不作为规则来源。参考图裁切、去背景或重绘时保留原件，并记录使用工具和处理方式。

资产约定：

- 源文件使用米制，记录对应实物毫米尺寸；Unity 按 1 单位代表 1 米处理。首个导入样板验证坐标轴、缩放与朝向转换。
- 地块、城市和骑士的枢轴为底面中心；道路为长度中点；船另记录水线高度。所有同类组件保持一致。
- 地块记录边长、厚度和棋子摆放基准面；棋子记录占地与最高点。实际数值以实测和样板验证结果为准。
- 渲染模型与交互碰撞分离。高地形可以单独淡化，地形装饰不拦截边与交点选择。
- 源 .blend 与导出资产分开保存。默认考虑显式 FBX 和纹理导出；在 M0 验证后固定导出器及参数，不依赖隐式导入过程。
- 先保证轮廓和识别，再根据整桌实测性能设置面数、纹理与 LOD 预算。
- 每个样板输出顶视、侧视、默认游戏相机与拥挤节点四种预览。
- 可复现记录包括参考编号、脚本、种子、参数、工具版本、生成提示词、材质版本和导出参数。

建议的目录职责：assets/references 保存参考；art/source 保存 Blender 源文件；art/recipes 保存脚本与参数；art/exports 保存中间导出；Unity 工程的 Assets 保存实际使用的资产。后四项在生产工具验证后创建。

同一资产的完成条件是源文件、生成配方、导出模型、依赖纹理、清单与预览齐全，且能从干净输出目录重新生成。原始参考和不可复现的源资产需要备份；大量二进制文件录入前确定 Git LFS 或独立备份方式。

参考：[Blender 4.5 LTS](https://www.blender.org/releases/4-5/)、[Blender 命令行参数](https://docs.blender.org/manual/en/4.1/advanced/command_line/arguments.html)。执行命令和 API 以实际安装版本验证为准。
