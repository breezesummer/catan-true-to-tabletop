# 2026-11-01 底部透明手牌区域不再拦截棋盘

## 原因与修改

`OperationDock.BlocksBoardInput` 无条件拦截整个 `HandViewport`（逻辑y=680至889），鱼牌的 `FishingDock.Contains` 也拦截整个相同区域。底部岸线落入此处时，输入在顶点拾取前被拒绝并清除建筑虚影，与海洋板块是否存在无关。上一轮补海与静止虚影恢复未覆盖这条路径。

- 资源／发展卡只保留实际牌面、正在拖动的手牌、悬停稳定边缘和已绘制控件的命中；透明留白放行棋盘。
- 可见的底部托盘显式注册命中，避免移除大范围拦截后发生穿透点击。
- 鱼牌按实际绘制位置及抬起状态记录牌面边框范围，保留捕鱼操作栏拦截，空白鱼牌区域放行。
- 手牌滚轮只在实际牌面命中时使用，空白区域不再同时滚动手牌和缩放地图。
- 四种模式共享上述输入组件；未改变规则、通信、合法建造判定或地图数据。

## 验证

复用 `FishingF6EditorVerification --f6-sample` 并增加针对性检查，最终全部通过：

1. 在实际GameView已绘制UI后，检查x=400/720/1000、y=690/710/800的九处透明留白均不拦截，y=870可见底栏仍拦截。
2. 取基础地图最下方三个顶点，依次平移到逻辑坐标(720,710)，经实际 `DockBlocksMouse` 组合拦截链、`VerificationPick` 顶点拾取和 `PreviewPiece` 虚影生成检查通过。这里验证的是屏幕坐标驱动的同一路径，不是物理鼠标整局试玩。
3. 鱼牌打开时空白(1000,710)不拦截，实际鱼牌(380,755)与操作栏(685,616)仍拦截。
4. 原有GameView鱼页签、右键说明、支付取消、确认扣牌及虚影检查通过；实际支付截图已审看。

日志标记：`BOTTOM_BOARD_INPUT_OK`。初次尝试原生MouseMove队列时，系统鼠标坐标没有随注入事件更新而仍位于右侧面板，导致悬停检查失败；改为上述确定的屏幕坐标链检查后通过，未将前次失败计为验收。

结果见[窗口检查](窗口检查.json)。其中脚本通用结果描述的移动端长按不属于本次Win64执行范围；本轮未执行Android真机或四设备联机。
