# 2026-10-21 — 联机展示等待与棋子增量刷新

按用户要求覆盖内测版 **1.6.16**，不递增版本号，不作为正式发布。Windows、Android 与服务端产物仍位于 `game version/1.6/Catan1.6.16-Room-Lifecycle`。

## 改动与边界

- 权威快照附带同一席位可见的最近 64 条展示记录及覆盖起点。客户端先合并记录，再通知显示层；正常连续同步不再为了展示新局面多等一次历史 HTTP 请求。完整历史仍独立分页，近期记录不会推进分页游标。
- 初次入桌保持不重播旧动画；近期记录覆盖不足时仍等待完整历史补齐，不能以超时跳过的方式丢失发展卡或进步卡动画。重新开局清除上一局记录；相同修订、重复命令和迟到响应不重复插入历史。
- 同一修订的心跳／推送不再重复解析近期展示记录；只有新修订才处理该记录。
- 四种规则棋盘按分组、稳定位置 ID 和外观状态保留现有显示对象。资源、回合等非棋盘变化不再销毁全部棋子。建造、移除、所有者改变、骑士等级与激活、城墙、大都会轨道、军舰、强盗／海盗及商人变化分别更新相关对象；蛮族位置不变时复用模型。
- 动画模型缓存保留未变化的棋子，保留升级、替换和移动动画需要的旧模型。根节点名称、拾取层级、落地前目标隐藏及本回合高亮沿用原约定。
- 服务端按房间修订及观看席位缓存可见投影，避免同一局面在心跳、轮询与预览请求中反复计算和编码。每次请求仍检查身份、控制权和房间状态；不同席位不共用私有投影。
- 规则核心、指令验证、权威随机数、存档格式及 AI 决策没有修改。新增响应字段为协议 v3 的可选字段；旧服务端未携带时客户端仍使用原历史流程。

本轮集中处理历史等待、棋子重建及重复投影。750 毫秒推送检查、每秒 HTTP 后备同步、远程预览排队和锁内持久化仍保留，不宣称所有延迟来源已消除。
