# 三国争霸 B4 工程验收记录

日期：2026-10-23（Asia/Shanghai）。游戏版本保持内测版2.0.1。本轮产物是本地开发包，未正式发布或部署云端；不改变 M7／M8 的产品验收状态。

三国规则与会话检查按用例名去重后 **558／558通过**，包含B4的192项及B1–B3回归366项；20个正常完整局全部通过。最终产物及日志指纹见[构建指纹](构建指纹.json)。机器统计、精确失败名单、证据路径、时间和已有 SHA-256 见[测试结果](测试结果.json)。

## 修复过程与复验

首轮20个完整局为7通过、13失败，保留原始证据 `b4-complete-sessions.trx`，不作为最终通过结果。自动判定得到最终值却没有待选者时曾停在无动作阶段；虚拟牌支付全部底牌后的附加费用、外层净手牌重复计数、历史来源身份等问题随后分别修复与复验。

三国统一检查的7个失败包括6个交易／随机夹具断言和1个遗忘部落四人完整局。6个夹具案例已由最后专项同名案例通过覆盖，最后一个完整局由最终20局中的同名案例通过覆盖。精确用例名保存在机器统计中，不隐藏中间运行结果。最后历史／转换隐私修复另有97项相关案例通过（含4项新增），不把它与较早编译的完整局混称为最终每一行代码的重复长局测试。

## 原模式与本地网络

旧模式快速回归共1171项：1149通过、22失败。将失败完整用例名按区分大小写的集合比较，与[B3既有失败基线](../three-kingdoms-b3/测试结果.json)的22项**逐项完全一致，新增失败为0**。这保留了既有展示／旧牌名／历史断言问题，不表示旧模式全绿。旧模式108完整局本轮未重复运行，不计为本轮证据。

网络协议、房间和权限回归153／153通过；本地HTTP／WebSocket服务与客户端回归71／71通过。覆盖同时选将独立令牌、旧房间修订兼容、包哈希、幂等与隐藏信息等本地自动路径。没有外网多人实测、四真人长局或用户整局试玩证据。

## Windows 与 Android

实际Windows程序以自动验证入口运行M4/M5各三人／四人，4个配置通过，记录36次保存恢复、8次主动隐退、4次本地重开和4次技能选择。运行启用图形；`result.json` 的截图数量为0，`fullUiPixelsVerified=false`，因此不记为截图或完整界面像素验收，也不等同真人鼠标／触控操作。

最终Windows客户端及随包服务增量构建成功；最终Android ARM64 APK增量构建及签名验证成功，耗时109.3秒。最终产物及最后构建日志指纹见[构建指纹](构建指纹.json)。Android没有可用真机，本轮没有安装运行、触控或性能验收。

另由主代理在实际Windows程序执行鼠标操作，观察主菜单启用三国四人、本席4候选选2、2选1登场与统一公开屏障通过。证据为本轮实时屏幕截图和观察报告，没有另存PNG；这只覆盖上述局部流程，不能扩写成完整UI像素或用户试玩通过。过程中发现菜单残留B3说明；最终Windows程序重开后进入城市与骑士向导，已目视复验“三国争霸 B4（30张完整武将）”及“已开放30将、51技能，同时选将与自动阶段；支持本地及联机对局”。

城市与骑士的默认13分胜利目标保持原规则。B4的13／17是三人／四人同时预留候选所需的最小武将实体数，不是胜利目标；不能将两者混写。

自动Player结果文件为 `game version/2.0/Catan2.0.1-Three-Kingdoms-B4/verification/result.json`。只记录其公开统计；同目录的候选、手牌、随机状态或权威存档不复制进本验收目录。

## 复跑入口与证据保护

仓库根目录加载 `tools/development/Enter-DevEnvironment.ps1` 后，使用配置的SDK运行：

```powershell
dotnet test tests/Catan.Rules.Tests/Catan.Rules.Tests.csproj -c Release --filter 'FullyQualifiedName~ThreeKingdoms'
dotnet test tests/Catan.Network.Tests/Catan.Network.Tests.csproj -c Release
```

这两条是复跑入口，不代表本次又重复执行一遍。实际运行的范围、时间和结果以本目录的证据记录为准。完整局的 `CATAN_B4_TRACE` 应指向本地私有目录，跟踪包含权威数据，不提交其 `checkpoint` 或带命令载荷的进度文件；本目录只留公开统计及证据指纹。

详细鼠标步骤与观察边界见[Windows交互观察](Windows交互观察.md)。自动Player运行发生在最后历史编号和菜单文案修复之前；最终产物另有构建及菜单复验，两组证据分别记录。
