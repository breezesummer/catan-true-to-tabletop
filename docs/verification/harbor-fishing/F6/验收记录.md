# F6 产品验收记录

日期：2026-10-30（Asia/Shanghai）。范围见[实施方案](../../../海港大师与捕鱼实施方案.md)。本阶段分别记录工程、设备、外网和用户试玩结论，不以编辑器或回环测试代替实机结果。未正式发布、未部署云服务、未调整发布版本。

## 实现与发现

- 用 Blender MCP 制作并接入13件模型与同源图标：海港奖励牌、1／2／3鱼、统一背面、旧靴、六渔场和湖泊。米制估算、底面中心枢轴、URP材质，无交互碰撞体。全部资产和配方见[资产清单](../../../../art/recipes/harbor-fishing-v001/资产清单.json)。
- 四模式使用公开地图和稳定顶点定位渔场；按相邻陆地朝海摆放，最多20个候选避让港口与其他渔场。地图未变化时复用已有对象；湖泊只按公开地形加载，不读取隐藏探索池。普通刷新不生成新网格、材质或网络消息。
- 鱼筹码、鱼池背面、公开弃置顶面、旧靴头像标记和海港奖励采用模型图标。对手仅显示背面和枚数；支付仍由玩家确认，展开按钮可关闭未提交草稿。提交、取消、恢复均沿用权威入口。
- **修复真实 WebSocket 的推送断线**：房间创建／加入检查通过后，服务端此前只绑定身份，丢失了附加玩法版本；随后推送再检查能力时遭拒，关闭连接。本次保留成功请求已验证的附加玩法与三国版本声明，覆盖全量与增量流、重连以及从普通房间切换。没有替客户端填入最新版本，旧客户端仍被拒绝。
- 外观复核修正凹岸朝向、窄水道渔场重叠、湖泊六边形朝向，以及合并网格后单根FBX轴向被运行时覆盖的问题。模型验证改用实际游戏的实例化入口；不把资源默认旋转下的检查当作运行时通过。

本轮未修改规则算法、规则版本、命令数据或权威存档格式。组件规则来源仍为本地锁定 `TB25.pdf` 第4、9—10页；地图组合沿用F0、F4、F5定稿。

- 房间专项覆盖四席鱼支付、预览无副作用、重复命令、隐藏信息、换抽待决重连、服务保存恢复、配置和旧客户端拒绝。
- 复用 `FourSeatTransportMeasurementTests`，新增捕鱼开／关两组，四条真实回环WebSocket比较21秒静止窗口，再提交合法村庄并检查其余席位收到推送。
- 复用 `IncrementalTransportTests`，新增捕鱼开／关两组；同一权威桌40条命令同时观测全量与增量，随后30条命令仅保留四条增量流，断开其中一条并重建，检查完整基准和视图一致性。
- `FrameCostDiagnosticsTests`、发送队列边界、增量客户端、切房、服务诊断等包含在最终101项中。脱敏队列测量峰值为1，没有队列满事件；测试清理时主动中止套接字产生的关闭记录单列在[队列测量](队列测量.json)。

## 本机渲染测量

Mac17,3／Apple M5，Unity 6000.3.25f1，1920×1080 GameView，四模式各调用100次实际 `M6Refresh`，刷新前后六渔场实例ID保持一致。数字包含整次桌面刷新与反射调用，不是仅渔场函数成本，也不是GPU耗时。

| 模式 | 平均毫秒 | 最大毫秒 |
| --- | --- | --- |
| 基础 | 3.46 | 7.09 |
| 城市骑士 | 3.73 | 8.93 |
| 航海 | 6.97 | 16.56 |
| 双扩展 | 6.78 | 16.74 |

原始数据在 `mobile-art-final/*-刷新性能.json`。同一双扩展局面关闭／开启六个渔场对象，各等待30帧后采样120帧：平均16.666／16.664毫秒，最大17.130／17.116毫秒，见[关闭](mobile-art-final/模型关闭帧间隔.json)和[开启](mobile-art-final/模型开启帧间隔.json)。两组湖泊均保留；这些是编辑器墙钟帧间隔，受帧率限制和编辑器调度影响，不能据此宣称主线程预算、Android帧率或长时间稳定性达标。

发送队列峰值与70次命令提交计时已从既有脱敏日志汇总至[队列测量](队列测量.json)。`room.commit`只测序列化和测试用空存储提交，不含此前规则执行；本轮没有独立纯规则耗时采样，不将其冒称规则耗时。后续设备验收仍须取得目标机主线程／GPU和长时数据。

## 开发构建

Windows x64客户端、随包自包含房间服务和Android ARM64 APK全部构建成功；两端Unity日志均有规则执行／权威存档往返成功标记，另有各自构建成功标记。产物与客户端／服务程序集SHA-256见[构建结果](构建结果.json)，Android使用IL2CPP、OpenGLES3、最低API26，详见[构建信息](Android构建信息.json)。

## 复现

```sh
source tools/development/Enter-DevEnvironment.zsh
dotnet test tests/Catan.Network.Tests/Catan.Network.Tests.csproj -p:UseArtifactsOutput=false -p:DirectoryBuildPropsPath="$PWD/Directory.Build.props"
dotnet test tests/Catan.Server.Tests/Catan.Server.Tests.csproj -p:UseArtifactsOutput=false -p:DirectoryBuildPropsPath="$PWD/Directory.Build.props"
```

Unity完整检查入口 `FishingF6EditorVerification.Run`；参数 `--fishing-f6-verify` 后给 `.local` 内输出目录；加 `-catan-mobile-ui` 进入1920×1080移动端预览，加 `--f6-visual-only` 只复核模型与渲染。`FishingF6SampleVerification.ReimportAndVerify` 重新导入并验证13件资产；`FishingF5EditorVerification.Run` 可继续复核第三批地图和新世界布港口前后。私密测试存档只留 `.local`，不纳入公开证据。

双平台开发验证入口：`python3 tools/validation/build_harbor_fishing_f6.py`。使用独立英文工作区、临时APK测试签名和开发构建，不覆盖源工程设置或正式发布目录。临时签名APK不能覆盖原签名安装。
