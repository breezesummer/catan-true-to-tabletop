# F2 基础捕鱼验收记录

日期：2026-10-29（Asia/Shanghai）。F2达到基础规则阶段退出条件，下一工作包为F3。依据为本地锁定的 `TB25.pdf` 第9—10页，以及 [F0定稿](../../../harbor-fishing/F0规则定稿.md) D02—D05。游戏发布版本保持内测版2.1.0。

## 实现范围

- `TradeModules/FishingRules.cs` 共用筹码池、抽取、换抽、支付、私密投影和守恒检查；`M2Fishing.cs` 负责基础版效果及阶段桥接，不依赖Unity、物理、UI或网络。基础版通过 `TradeModuleOptions.Fishing` 开启，可独立于海港大师使用。其他模式明确拒绝捕鱼配置。
- 固定29枚鱼（11枚1鱼、10枚2鱼、8枚3鱼，合计55鱼）与1枚旧靴，每枚稳定ID只能在供应、弃置或某玩家处。旧靴不进入鱼手持上限、支付或弃置。只在初始化和供应耗尽后的弃置洗回使用权威随机源，普通抽取弹出池首。
- 第二座开局村庄邻接任一鱼源时抽1枚；旧靴占一次机会，不补抽。正常产出在基础资源结算后处理，按行动者起顺时针、同玩家按源ID与顶点ID冻结队列，村庄1枚、城市2枚。
- 上限是7枚筹码。满额且仍应抽时进入 `FishReplacement`，由实际获鱼者处理；记录待决ID、队列、游标、剩余次数和本回合换抽标记。弃1换1后停止该玩家本次剩余机会；拒绝也停止，但不消耗本回合次数。抽到旧靴后为6鱼＋靴，不补抽；城市普通第一抽旧靴仍保留第二次机会。真实结束回合重置所有玩家的换抽次数。
- 五行动：2鱼移出强盗且不偷牌；3鱼随机偷取任一有资源的对手；4鱼从供应取自选资源；5鱼免费修路；7鱼免费取得牌堆顶发展牌。均限本人自由掷骰前／行动阶段。目标、库存、筹码归属及数量先校验，事务副本中一次支付和执行，多付不找零。发展牌保留购买回合与使用限制，建设保留连接、阻挡和棋子库存条件。
- `SpendFish`、`PassOldBoot`、`ResolveFishReplacement` 使用现有唯一命令ID，并要求 `ExpectedEventSequence` 等于当前状态序号。换抽另校验 `DecisionId`。重复ID先返回原回执，不重抽或重扣；不同内容复用ID、过期状态、越权与非法目标均拒绝。预览不提交任何状态或随机调用。
- 旧靴只能交给公开分数不少于自己的另一玩家；隐藏胜利点不参与比较。显示分数不变，仅本人目标提高1分，允许超过配置上限。自由窗口结束后只检查当前行动者的胜利，强制待决期间不提前终局。
- 湖泊固定2／3／11／12，强盗可进入湖泊并同时阻断四个号码；不能进入渔场。开局强盗在棋盘外，之后掷7或骑士仍可正常入场。鱼不参与掷7手牌计数、玩家交易和强盗偷取。
- 本人视图显示自己的筹码ID及面值；其他玩家只有枚数、公开旧靴与换抽次数，弃置只公开面值，不发可追踪的Token ID。所有视图均不含鱼池顺序、队列和随机状态。AI现有资源牌权限不增加鱼面值权限；鱼偷牌历史只对双方显示牌种，对无关者显示数量。

- F01基础第二村奖励与旧靴通过；城市骑士开局城市留F3。标准图内圈湖泊与海岸渔场不会在同一顶点相交，当前入口对开局鱼源使用“存在任一源”且只创建一次抽取，不伪造标准图多源重叠。
- F02：合法渔场两端检验村／城；同一湖泊三个相间顶点检验B／C／A顺序与1／2／1枚。原草案把三个合法建筑放在同一三顶点渔场，会违反距离规则，测试采用真实合法拓扑验证等价顺序。
- F03—F05：7枚换靴后剩6枚并停止；6枚普通城市先抽靴再抽鱼达到7枚；本回合已换不再换、拒绝不消耗、结束回合重置。
- F06：共用抽取函数直接使用合同指定的3枚小池，检验先发、洗回、后发不足和停止；该抽取夹具不冒充满足30枚守恒的完整局。正常完整局另独立检查全部30枚守恒。
- F07—F12：五行动及窗口、非法支付／目标、幂等和过期状态、湖泊与强盗、公开分传靴、个人胜利通过。
- N01基础待决与支付恢复、N02基础及AI鱼视图隐私、N03基础旧档／开关／版本、N04组件守恒通过。进步牌响应、网络能力协商、代操授权与旁观会话均留F3。
