# F3 首个产品切片验收记录

日期：2026-10-29。对应[实施方案](../../../海港大师与捕鱼实施方案.md)F3，规则依据为[F0定稿](../../../harbor-fishing/F0规则定稿.md)，沿用内测版2.1.0；本轮未发布或部署。

## 实现范围

基础版与城市骑士标准图均支持3／4人、独立捕鱼开关、与海港大师同时开启；城市骑士可叠加三国完整包。主菜单、本地保存／载入／重开、房间配置、服务恢复、客户端能力协商、产品AI及桌面操作已接入。航海／双扩展捕鱼仍明确禁用，留F4／F5。海港大师继续沿用F1兼容范围。

城市骑士使用共用有限鱼池和抽取规则：开局第二座城市只给一枚；正式资源、商品、水渠及三国收获响应结束后，按已冻结的座次和建筑额度抽鱼。新增权威冻结产出队列，7枚上限选择归属实际受益人，保存队列、待决ID、规则身份和随机状态。鱼本身不计入资源／商品手牌、七点弃牌、水渠收入或三国牌流；五行动所得资源、商品、进步牌及真实建设再进入对应原有处理。

来源：`.local/reference-cache/traders-barbarians/v001/TB25.pdf` PDF第9—10页、`.local/reference-cache/traders-barbarians/v001/FCK.pdf` PDF第1页；具体文件路径以[本地规则索引](../../../../assets/references/rules/README.md)和F0来源锁为准。七鱼选择进步牌堆、旧靴个人门槛及特殊技能边界按F0裁决实施，不宣称额外项目裁决是官方原文。

## 关键行为

- 五行动可在本人自由掷骰前／行动阶段执行，事务内先预检目标再扣筹码；取消预览、非法／过期命令不扣费、不推进随机，重复确认不重复执行。五鱼只修道路，七鱼选择贸易／政治／科学牌堆并遵循原进步牌上限和公开分规则。
- 三国组合：鱼支付建设记实际资源成本0；不触发强盗专属免疫或“成为技能目标”；景略拒绝主动选取禁获资源，随机偷到禁获牌则留在原处、不重抽、不退鱼；盟友不可作为偷牌目标。旧靴只增加持有人个人目标，不增加盟友目标；貂蝉代操使用资产所属者筹码与授权视图。鲁肃交换后湖泊仍须位于内圈，渔场留在固定空间位置。
- 对手只见鱼筹码枚数、旧靴归属、公共弃置面值；不见对手筹码ID、面值、鱼池顺序、随机或队列游标。偷牌历史仅偷牌双方见具体资源／商品，对其他席位只见数量。
- 桌面筹码条支持点选筹码、支付面值预览、确认／取消；头像选偷牌或旧靴接收人，棋盘选道路／强盗，进步牌选颜色。满额待决直接点筹码换抽或放弃。右键／长按复用原输入层显示筹码说明；公开枚数及旧靴位于头像两侧，湖泊与渔场有轻量标记。
- 产品AI只用授权筹码和合法行动投影，按最少浪费、再最少筹码数选择支付；优先即时获胜建设，再考虑解封锁、补资源、扩路和抽牌，低面值优先换抽。鱼源价值参与开局选址，旧靴门槛参与胜利判断。

## 网络与性能证据

基础、城市骑士、三国城市骑士各用四人权威房间，按产品AI正常推进到两次鱼支付。验证预览无副作用、重试幂等、四席隐私、各席完整视图与增量还原一致，支付后重建服务并恢复原席位。另一路保留筹码自然达到7枚，验证非行动者换抽权限、重连保持待决及鱼面值、服务重启不改随机，原有AI接管政策能继续处理；没有修改“下回合接回”的既有政策。

新增房间版本 `harbor-fishing-f3-v001`。开启模块的房间要求创建、加入、准备、重连和操作请求声明支持版本，旧客户端明确拒绝；关闭模块的旧房间兼容。配置修改沿用原准备清除机制，重开保留开关。城市骑士新存档使用F3模块身份，基础鱼规则仍保留F2存档身份，海港独立存档保留F1身份。
