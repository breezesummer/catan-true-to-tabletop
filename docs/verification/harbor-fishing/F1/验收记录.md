# F1 海港大师验收记录

日期：2026-10-29（Asia/Shanghai）。规则依据为 `TB25.pdf` 第4页、`FAQ.html` 大都会及遗忘部落港口问题，以及 [F0 D01／D05／D06](../../../harbor-fishing/F0规则定稿.md)。本轮只实现海港大师，捕鱼与旧靴仍按后续阶段实施。

## 实现范围

- `TradeModules/HarbormasterRules.cs` 统一计算有效港口建筑：村庄1点、城市与大都会2点；同一顶点只计一次，库存／未领取港口不计。城市损害后仍有效的村庄计1点，村庄自身倒塌计0点，降级城市库存不额外计分。
- 达到3点后获得唯一的2胜利分奖励；持有人最高并列时保留，严格超越时转移，损失后的唯一最高者接奖，多人并列则回公共区。使用个人建筑归属，不使用联盟共享贸易权限。
- 基础、航海、城市骑士、双扩展统一接入。三国使用当前港口位置及损害记录，地图事务完成后重算；有强制待决时不提前结束，非行动玩家不能因奖励转移直接获胜。奇观、布匹等剧本终局条件保留。
- 默认目标加1，自定义输入已表示最终基础目标，不再追加。海盗群岛仍禁用，未改其分数上限。
- 新模块身份为 `harbor-fishing-f1-v001`；启用时权威存档格式分别为102／103／104／105，让旧程序显式拒绝；关闭时保留2／3／4／5及原随机调用路径。恢复继续通过完整命令重放比对，拒绝未知模块版本、错误持有人及删除模块字段的伪造存档。模块状态在事务副本中独立复制。
- 本地“同桌设置”增加海港开关；原奖励区显示归属和2分，分数详情显示港口点数和奖励。四模式宿主、保存恢复及重新开局保持配置，单独记录推荐／手动目标选择；返回菜单后切换开关仍保留手动输入，推荐值则继续自动更新。旧包装存档缺选择字段时按原有手动值行为读取。城市骑士奖励区已压紧间距，避免遮住历史面板。
- AI只使用所属公开视图，增加港口开局／建设估值及抢奖收益；基础AI覆盖立即获胜，城市骑士与双扩展将港口奖励纳入建设得分预测。关闭模块不改变港口策略数值。另修复完整局暴露的城市骑士AI联盟骑士查找：合法激活目标可属盟友，按全棋盘公开骑士读取等级，避免只查本人集合导致崩溃；不改变骑士所有权或合法操作权限。

## 复现入口与后续边界

```sh
source tools/development/Enter-DevEnvironment.zsh
dotnet test tests/Catan.Rules.Tests/Catan.Rules.Tests.csproj -p:UseArtifactsOutput=false -p:DirectoryBuildPropsPath="$PWD/Directory.Build.props" --filter FullyQualifiedName~HarbormasterTests
"$UNITY_EDITOR" -projectPath "$PWD/Unity/Catan" -executeMethod HarborF1EditorVerification.Run --harbor-f1-verify "$PWD/.local/development/harbor-f1/ui" -logFile "$PWD/.local/development/harbor-f1/unity-ui.log"
```

Unity运行前须按 `tools/development/build_macos.py` 的 `assemblies` 步骤编译并同步Core／AI／网络DLL。测试原始TRX保留于两个测试项目的 `TestResults/harbor-*.trx`，编译日志保留于 `.local/development/harbor-f1/`；摘要不依赖本地绝对路径。

F1达到规则、本地产品入口、AI和存档的工程退出条件。F2接着实现基础捕鱼；海港房间设置、客户端能力协商、联机重新开局和四人重连随F3接入，当前房间入口没有海港开关。三国全技能的捕鱼交互、Android真机触控、Windows实际程序、四人外网及用户整局试玩仍按F3—F6验收。本轮未制作模型、未输出发布包、未部署；不改游戏发布版本，保留既有美术、项目配置及其他日志改动。
