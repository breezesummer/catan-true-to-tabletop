# 联机性能第一批实施与验证

日期：2026-10-25（北京时间）。完成 [性能方案](../../ONLINE_PERFORMANCE_OPTIMIZATION_PLAN.md) P0–P3 的工程实施及本轮指定的后台／兼容验证。用户在窗口采样受阻后明确本轮只完成后台工程与兼容验证，前台体验指标保留后续验收。版本沿用内测版2.0.2；产物为本地性能候选包，不执行正式发布、云端部署或M7／M8阶段变更。P4 的即时推送及P5的增量同步留在第二批。

## 实施范围

- P0：沿用请求编号、构建 GUID、焦点和逐帧诊断，增加正文收齐、后台排队、工作线程完整解析、分配量、线程池活动数、主线程应用和首个 Repaint 提交的单调时钟记录。工作线程结束及主线程入队可由同一时钟域的持续时间与排队时间定位；首个 Repaint 是客户端提交展示的时间，不是屏幕实际发光时间。日志保持白名单、有界、后台写盘，平台不支持的分配诊断或日志启动失败不阻断回包。
- P1：默认直接读取 JSON，保留原 XML 路径作诊断回退，不引入动态代码生成或新增运行时库。后台准备完整外层回复、所属规则包的玩家视图及两类历史；主线程切换已准备的数据。解码最多2个工作任务、8份待处理消息及8MiB正文；主线程最多32个已入队回调，通过背压保留顺序。会话取消、切房、连接接管及旧修订均受原代次检查约束。历史索引按命令／技能事件键增量维护，内容相同不失效，补充结果原位替换。
- P2：协议仍为3，成功列表／握手通过既有 `Code=CompactRepliesV1` 协商轻量操作，不向旧严格解码器添加字段。新增 `PreviewCompact`、`HistoryCompact`、`Heartbeat` 和 `CommandReceipt`；原操作保留全量回复。轻量路径直接跳过游戏投影，历史页不重复附带近期展示历史。成功回执与实际视图修订分开；状态或必要事件未就绪时保留待确认锁，并通过完整 Get 补齐。回执先到、状态先到及旧服务回退均有覆盖。
- P3：缓存历史水位过滤、骰子历史、行高、累计布局、常用样式及卡面描述；历史滚动以二分定位可见行。镜头平移直接移动相机，棋子动画缓存起点和渲染器，播放中不再复制动画列表或查找组件。桌面卡纸等显示物件使用最多64个闲置对象的池，收牌展示队列设256条上限；出牌特写最多4条，正常时长不缩短，超限直接恢复最新视图并显示恢复摘要。大积压保留完整历史；技能结果补写只消费新增收牌和公开特写。按当前规则包异步预热卡面，预热引用预算64MiB，不加载其他主题。

网络逻辑视图与画面刷新分开：同一帧的可替代视图在 LateUpdate 合并刷新一次，事件、命令回执和历史游标不合并丢弃；刷新前暂不允许依赖新局面的提交。镜头不依赖命令待确认状态。

## 固定数据解析与通信对照

基线是本次工作开始时已提交的 B5 源码 `6f0e47d1`，不是方案所述14点的 B4 二进制。新旧解析器在同一进程环境、同一线格式与相同 JSON SHA-256 数据上比较；使用真实四席组合地图投影和合成公开历史，不读取真实玩家手牌或随机状态。见 [直接解析](decode-direct.json)、[原解析](decode-legacy.json) 和 [工具源码](../../../tools/validation/OnlinePerformanceProbe/Program.cs)。

| 正文实际字节 | 串行样本 | 原完整解析 P95 ms | 新完整解析 P95 ms |
| ---: | ---: | ---: | ---: |
| 10,520 | 30 | 1.86 | 0.37 |
| 71,737 | 30 | 44.23 | 1.68 |
| 256,208 | 10 | 1,426.19 | 6.33 |
| 1,048,634 | 3 | 43,076.70 | 23.74 |

70KB档串行完整解析 P95 降低约96.2%，当前线程平均分配从约651MiB降至0.87MiB。原 XML 路径在大段嵌套历史字符串上具有严重增长；1MiB档仅3个串行及4个并发样本，作为大包压力诊断，不能据此推断稳定 P99。10KB／70KB档另有各120个四工作并发样本。全部报告记录样本数、各档首次样本和程序集指纹；首次样本可能已预热部分类型，不冒充进程全冷启动。这里测的是完整必要解析，不含网络、解码调度或 Unity 帧率。

同一四席基础局、相同局面分别执行30次预览、30次历史页及四席各10次心跳，回复正文总量从908,820字节降至160,850字节，减少 **82.30%**；预览／心跳均不超过2KiB。见 [字节对照](compact-bytes.json)。该脚本覆盖轻量消息，不含完整对局推送、HTTP／TCP头、网卡出口或4Mbps限速，不能据此承诺真实四人整局节省82%。

## 回退与后续边界

- `--m7-legacy-decoder` 在客户端启用原 XML 解码，完整后台准备和有界应用队列仍保留。
- `--m7-legacy-replies` 禁用轻量回复协商；旧服务未声明能力时也自动使用原操作。服务回退返回未知轻量操作时，HTTP沿用原请求／命令编号重试原操作，WS心跳改回Get。
- 原协议字段和权威存档格式未变。客户端回退使用先前B5包；服务端切换另行执行，不在此次验证中替换生产服务。
- 四台设备、Android真机、60分钟长局、4Mbps出口整形与弱网矩阵属于后续验收。本轮不能据同机微基准、模拟器或单客户端窗口宣布上述目标通过。

14点B4原日志已轮转；本次另用既有收集器留存仍可读取的诊断，未将后续B5会话冒充该B4现场。方案中的现场统计仅按其既有证据边界引用。
