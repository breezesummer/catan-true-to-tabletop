本轮按“覆盖当前版本”执行。工作区同时进行的版本准备已将当前版本设为 1.7.0，本轮不另增版本号，也不修改该轮界面规划。构建路径沿用 `game version/1.7/Catan1.7.0-Ultra-Baseline`。

## 实测定位

独立 Windows Unity 客户端，1440×900，组合规则三人局；服务器执行 AI，验证驱动仅代替本席发送合法指令。局域网使用独立本机 HTTPS 服务，公网连接现有服务器并使用 WS。局域网 WSS 在本机 Unity TLS 实现下失败，按既有机制回退为带证书指纹校验的 HTTPS。采样期间没有同时运行本轮构建或测试。

`Stopwatch` 测量主线程网络响应解析、快照应用、权限视图解析、历史解析、棋盘刷新、动画更新及 OnGUI；另记录动画状态、帧间隔和 GC 次数。验证驱动的本地 AI 决策独立计时并从统计中剔除。所有公开样本仅含数值，不包含网络正文、凭据或手牌。

## 修改

- HTTP 和 WS 的完整响应解码移至后台任务。只传入独立字节副本，不在后台访问 Unity 对象、客户端可变状态或规则权威。HTTP 调用完成后返回原上下文；同一 WS 接收循环等待当前解码后才继续接收。原有主线程队列、修订号、重连代次、旧连接过滤继续生效。
- `WireJson` 缓存不可变类型布局及字段查找表，避免为每个地块、边、玩家和历史项反复反射。保留字段排序、internal setter、隐藏字段排除、未知/重复字段拒绝和根类型白名单。
- 建造表现只在权限视图对象变化时重新生成移动路线、建筑占位数组。逐帧插值、动画时长、高亮、历史等待与补齐规则不变。
- 采样默认关闭；显式 `--frame-profile <输出目录>` 启用。最终版额外记录 `ResponseDecodeWorker`，这是该帧收到的后台已完成任务总耗时，**不是主线程耗时，也不可加进帧预算**。最终采样确实记录到 74 次后台完成，最高 467.917ms，说明计算被移走而非被省略。

## 边界与后续排查

本次自动化以隐藏窗口运行，OnGUI 样本为零，帧循环也不代表显示器实际刷新。因此这些结果证明 CPU 阻塞来源和改进，**不能宣称可见窗口、完整 UI/GPU 或手机已经稳定 60 FPS**。前后是同规则、同配置的独立实时对局，并非同一随机局面回放；数据量和消息到达时机不同，不作精确百分比性能承诺。局域网优化前到达 120,000 帧记录上限，其余原始采样也受此上限约束。

后台解析仍产生分配与 GC，不能消除所有全局停顿。视图、历史解析和棋盘显示仍在主线程，首次入桌/切房的场景创建也仍会出现数百毫秒峰值；表中只统计动画活动期间。不要将这些不同阶段混作同一种卡顿。

## 复现

```powershell
# 已启动的独立局域网服务及其证书文件
./tools/validation/Test-M7FrameProfile.ps1 `
  -BuildRoot 'game version/1.7/Catan1.7.0-Ultra-Baseline' `
  -OutputRoot '.local/frame-profile-recheck' `
  -Endpoint 'https://127.0.0.1:47831' `
  -FingerprintFile '.local/frame-profiling/server/server-fingerprint.txt'

# 使用可用 Python 解释器汇总；也可直接解压本目录 csv.gz 检查各帧
python tools/validation/Summarize-M7FrameProfile.py .local/frame-profile-recheck/frames.csv
```

人工可见窗口试玩也可直接给游戏附加 `--frame-profile <绝对目录>`，正常退出后得到 `frames.csv`；无需自动验证驱动。最多记录 120,000 帧，退出时写盘，避免采样中逐帧磁盘 I/O。阶段计时为包含子阶段的时间，不可简单相加。正常运行不挂载采样组件。
