审查范围为 `tools/art/entity_pipeline.py`、`verify_entity_pipeline.py`、`rectify_entity_photos.py`、`update_entity_checklist.py`、`audit_entity_assets.py`、`verify_entity_assembly.py`，两层构建 wrapper、Windows 验证 wrapper，以及 Unity 的 `EntityAssetBuild.cs`、`EntityAssetGallery.cs`、`EntityAssetPlayerVerification.cs`。另核对资源卡和六角板块配方、城市/大都会 builder、城墙净空报告。

本次未发现需要阻止最终 Unity 构建的确定性代码缺陷。可核对的实现包括：

- 照片校正以原件 SHA-256 为入口，只执行记录角点的投影/分片仿射和旋转；输出限制在新版本源目录，已存在且内容不同的贴图默认拒绝覆盖。
- 模型是显式闭合网格，源单位为米。导出轴为 `-Z` 前向、`Y` 上向；生成和回读均检查底心原点、包围盒、材质、UV 与实际三角面。Unity 用导出后的预期坐标边界核对实际渲染器边界。
- Unity 材质按 Blender 材质名逐项显式绑定 URP Lit 和 PNG，缺材质或缺 PNG 会中止。模型不自动添加碰撞体，图库只加载公开美术 catalog，不读取规则状态、手牌、存档或随机状态。
- 薄卡背面 UV 沿宽度镜像，图库绕对应长轴翻面，保持翻面后的估算底面在支撑平面。旋转/翻面程序检查与此约定一致。
- 跨类型审计核对锁定照片覆盖、版本产物校验值、干净重建、Unity 资产集合、三角面与尺度、独立 Windows 报告和规则回归证据，避免仅由预期数量宣布完成。

主任务随后扩展 Windows 验证，本子任务已再次只读复核 `Capture()`、调用点和 C# 语法。现在每件资产均加载、检查材质、调用旋转/翻面方法并输出俯视图；另外每类第一件输出四视图，卡牌/板类输出代表背面，城墙输出两种装入件视图。按当前 74 件/18 类配方，预计为 74 张逐件俯视、72 张分类四视图、8 张代表背面和 2 张组合图，共 156 张；这是代码预期，实际运行数量以最终报告为准。共用 `Capture()` 在 `finally` 中恢复相机矩形与原活动 RenderTexture，并释放临时图像/目标；空图检查比较角落背景像素的 RGB 总色差，要求至少 50 像素总色差大于 15，适用于深色模型且不把固定亮度阈值作为成图依据。未发现新增代码需要阻止最终构建的确定性问题。
