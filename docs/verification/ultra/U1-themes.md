# U1 双主题基础与兼容验证

日期：2026年10月21日。版本：内测版1.7.2。工程功能已实现，ultra 为明确标注的开发占位；未将 U2 地形、玉牌、环境动态或 U7A 牌面重绘视为完成。实机与人工交互待验，因此不更新 M8 路线状态。

## 使用入口

主菜单「设置 → 桌面外观」或对局「Esc → 游戏设置 → 桌面外观」选择「真实桌游」或「豪华典藏版ultra」。原来的「原版／海洋／骑士」保留为独立的界面配色。

未保存主题偏好时默认真实桌游；选择只写入本机 PlayerPrefs，不加入存档信封、规则状态或房间协议。旧存档继续按当前本地主题显示，各客户端可以独立选择。

- Windows：[Catan1.7.2.exe](../../../game%20version/1.7/Catan1.7.2-Ultra-Themes/Builds/Windows/Catan1.7.2.exe)，含随包房间服务。
- Android：[Catan1.7.2.apk](../../../game%20version/1.7/Catan1.7.2-Ultra-Themes/Builds/Android/Catan1.7.2.apk)，Android 8.0 起、ARM64，版本代码 10702，已验证签名。这是开发构建，不是正式发布。

## 已实现内容

`BoardThemeDefinition` 固定两种名称、稳定标识、资产版本及桌面／光照配置；`BoardThemeController` 管理客户端选择。`M6BoardTheme` 将切换安排在 Update，取消未提交的本地预览、收尾建造副本和高亮，阻挡切换期间输入，从最新人类投影重建，再恢复相机和平移，成功后保存选择。加载失败恢复原主题并显示提示。

基础版、航海家、城市与骑士、双扩展组合都接入同一入口；地形、港口及分值标记、村城墙与大都会、骑士等级／状态、道路、船、强盗、海盗、商人、蛮族轨道与船、玩家供应区、操作缩略图及鼠标预览共用主题来源。建造动画复制已落成棋子，玩家色使用有限共享材质，避免复制时丢色。主题重建同时修复原地图重建路径丢失平移、组合地图丢失缩放的问题。

ultra 采用可由代码重建的米制几何占位，颜色与棋子形状保留规则识别性；不是已确认概念图的正式模型。旧厚板后处理和塑料修补只在真实桌游使用。规则点数图案、港口比例图案和所有牌面在 U1 显式共用现有信息资产；原主题资产未被覆盖。牌面演出队列和网络历史回调保留，不重置已消费事件，不取得隐藏牌或 AI 专用视图选美术。

占位模板是按公开资源路径缓存的有限集合，挂在停用的专用根下；实例随棋盘、HUD 和演出根回收。模板共享网格和材质，不随每次切换重复创建。此次覆盖后缓存固定为 44 个模板；这部分预期缓存计入驻留内存，不作为遗留场景对象隐藏。

## 实际验证

证据目录：[u1-1.7.2](u1-1.7.2/)。Windows 验收使用实际独立程序、D3D11、1440×900、隐藏窗口；相机截图通过 URP 显式渲染取得，不冒称包含完整 UI 或实际鼠标操作。

| 检查 | 结果 |
| --- | --- |
| 26 个规则／剧本／人数配置 | 启动及主题切换通过，覆盖全部当前支持的基础、两种扩展及组合配置 |
| 旧存档 | U0 普通、最大、拥挤、迷雾四份无主题字段的信封加载并切换通过 |
| 待决继续 | 从正常合法对局截取的 10 个局面通过；覆盖基础／组合开局道路、交易、强盗、弃牌、道路建设卡和扩展选择；切换前后权威字符串完全一致，随后经原 Submit 入口继续合法操作 |
| 相机及隔离 | 平移、视角、缩放保持；真实桌游无 ultra 实例，ultra 无旧厚板处理；人类投影与权威状态边界保持 |
| 连续切换 | 拥挤地图交替 22 次，覆盖要求的至少 20 次；无重复桌面、重播建造或残留隐藏正式棋子 |
| 错误恢复 | 在新主题重建完成后注入失败，恢复真实桌游、原权威字符串及原偏好 |
| 本机双进程联机 | 两个独立客户端分别使用真实桌游和 ultra；各切换往返、重连，最终同到第 3 回合／修订号 25；两端分别提交 6／7 条人类测试指令，无本地权威实例 |
| 独立规则与表现回归 | 288 项中 266 通过、22 失败；在修改前提交 `91a65db` 的隔离副本、相同环境与筛选下得到完全相同失败集合，没有新增失败项 |
| 构建 | Unity Windows 构建及校验通过；Android IL2CPP ARM64 构建和签名校验通过 |

全部局面与循环合计记录 75 次切换检查；该数量包括为固定测试起点重复请求当前主题的检查，不等于 75 次实际重建。联机报告中未执行的本地权威／相机测试字段保留默认 false，应结合报告模式阅读，不代表这些项目在联机中失败。

规则回归的 22 个既有失败集中在旧牌名、历史文字及分值牌展示预期与此前实体牌名修订不一致。详细案例及前后集合对照见 [regression-comparison.json](u1-1.7.2/regression-comparison.json)。本轮没有擅自修改规则或旧测试期待；不能将回归写为全绿。更广的完整规则套件曾启动但未完成，最终报告只采用上述已完成的 288 项对照。

### 对象与内存

以下取连续切换的预热后区间（cycle ≥ 4）。每轮切换后等待 5 帧，显式 GC 后再等 2 帧取数，针对回收稳定性检查，不代表正常逐帧分配表现。对象数量只统计活动场景；材质、网格、纹理是引擎驻留总数，包含有限模板缓存。内存为 Unity 已分配内存，不等于系统工作集或 GPU 显存。

| 主题 | 活动 Transform | 材质 | 网格 | 纹理 | 音源／相机 | 区间首尾内存差 |
| --- | --- | --- | --- | --- | --- | --- |
| 真实桌游 | 342 | 286 | 117 | 82 | 17／2 | +4,760 字节 |
| ultra 开发占位 | 529 | 154 | 73 | 81 | 17／2 | −32,768 字节 |

两个主题各自的对象和资源数量均稳定。真实桌游采样内存为 139,829,935–139,842,759 字节，ultra 为 138,811,879–139,205,511 字节；不据短周期小幅波动宣称长期零泄漏。每次新棋盘建立、旧对象延迟销毁前读取一次内存，观测最大值为 141,774,383 字节（约 135.21 MiB）；这是采样点最大值，不是连续记录的绝对峰值。

## 复现

先使用默认 `Build-Game.ps1` 构建，或分别执行 `Build-M7.ps1`、`Build-Android.ps1 -Arm64Only`。准备 U0 四份基线夹具，并生成本轮待决夹具：

```powershell
. tools/development/Enter-DevEnvironment.ps1
& $toolchain.dotnet run --project tools/validation/UltraThemeFixtures -c Release -- (Get-Location).Path ((Get-Location).Path + '/.local/ultra/u1-pending-v2')
& tools/validation/Test-UltraThemes.ps1 -Output '.local/ultra/u1-new-local'
& tools/validation/Test-UltraThemes.ps1 -Output '.local/ultra/u1-new-network' -Network -Port 47882
```

输出必须使用新目录，避免旧报告或房间 ID 混入。验收组件只在显式 `--ultra-theme-verify` 参数下挂载，偏好使用独立测试键；私有夹具、服务器存档及测试凭据只留在 `.local`，可提交报告只包含公开统计。

## 保留的待验范围

实际 Windows 人工操作检查启动后，用户按 Esc 停止了 computer-use，未继续执行窗口输入，故主菜单与对局界面的完整鼠标／触控流程不标为通过。`adb devices -l` 未发现设备，Android 安装、触控、后台恢复及发热性能仍待真机；本机双进程不能代替两台物理设备及真实网络环境。长期内存、U0 固定路线的帧时间对比、正式美术与用户外观验收也未在本轮完成。

因此本轮交付 U1 可玩的双主题基础和上述工程验证，不宣称全部实机退出条件或 M8 已满足；`docs/ROADMAP.md` 保持原状。
