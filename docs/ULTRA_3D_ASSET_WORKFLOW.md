# Ultra 三维资产制作流程与提示词

日期：2026年10月21日。用途：为《卡坦岛之三国争霸》的「豪华典藏版ultra」制作真实三维游戏资产，供后续任务分阶段复制执行。本文记录制作方法，不表示资产或阶段已验收。

## 一、共同目标与依据

为「豪华典藏版ultra」制作真实三维游戏资产，目标平台为 Windows 与 Android，使用项目现有 Unity／URP 工程。

执行前阅读：

- [项目简报](PROJECT_BRIEF.md)
- [开发路线](ROADMAP.md)
- [Ultra 主题实施方案](ULTRA_THEME_IMPLEMENTATION_PLAN.md)

五类地形以 [v006 原型](../assets/prototypes/ultra/v006/terrain-states/README.md)为已确认的美术基准。其他资产核对各自确认状态，不自动视为已确认。

整体风格为暖光下细腻、鲜活的三国微缩沙盘。保持原型的轮廓、色彩层次、材质尺度与自然疏密，不擅自改成日式都市、像素风或粗糙低多边形风格。

生成图片是参考资料。最终必须交付真实网格、UV、材质、源文件、导出文件及游戏内验证结果。生成图的「实机感」与真实游戏截图分别标注；生成多视图的正交性及结构一致性需要检查，最终结构基准由同一真实模型渲染。

本轮只制作指定资产，不自动扩大到全部地形、全部动画或全牌面。按任务涉及的阶段执行，下列阶段共享本节约束；实际提交给图片生成工具的每条提示词必须独立完整。

## 二、阶段一：分析原型，确定制作规格

本轮资产：【填写资产名称及参考文件】。

先分析参考图，输出：

1. 必须保留的外轮廓、主要高差、构图、色彩分布、材质特征和关键细节。
2. 参考图无法确定的背面、底部、内部与尺寸。将补全内容标为设计推定，不称为原图还原。
3. 组件清单，区分唯一资产类型、参考图中的实例数量及建议变体数量。
4. 区分真实几何、地表纹理、可复用装饰、可动画部件和独立信息组件。
5. 从工程读取地块尺度、摆放基准、边与交点净空。找不到的参数标为待验证估算，不凭图片确定精确尺寸。
6. 根据同时可见数量提出面数、材质、纹理与 LOD 预算，并说明预算适用范围。

地形专项要求：

- 矿石为连绵高山，砖为圆润丘陵。
- 草原为新疆式鲜绿草坡，不放石头，原始态保留少量羊。
- 麦田呈现金黄茂盛的秋季丰收感。
- 森林清新繁茂，有自然层次。
- 地形中央连续，不为点数预留圆形空地。
- 悬浮薄玉牌独立制作，数字与概率点由准确的数据排版。
- 原始态、海岸和局部开发采用兼容模块，避免制作三套无法组合的整块模型。
- 局部开发遵循现有三分之一区域方案；不同玩家配色、建筑升级和存档恢复不得破坏布局。
- 六条边与六个交点保留工程要求的道路、建筑和操作空间。

若确需补充风格参考图，明确标注为「目标效果参考」，不能标注为真实游戏截图。已有确认原型不无故重新设计。

## 三、阶段二：拆分资产并编写独立生图提示词

依据阶段一清单，为需要补充参考图的资产生成独立提示词，输出 Markdown 提示词合集。

按可复用资产类型拆分。同类树、草、羊制作有限变体，再按布局实例化；不将每个可见实例都制作为独立资产。整块可旋转棋盘地形不使用分层背景建筑图替代真实几何。

每条提示词必须包含完整的：

- 输入参考文件及目标对象定位；
- 对象名称、结构特征和材质风格；
- 必须保留的细节；
- 允许推定补全的区域；
- 视角、背景、光照与画面边界要求；
- 本张图不得出现的其他对象。

不得使用「同上」「沿用通用要求」等依赖其他提示词的表述。调用项目可用的 ImageGen 工具，不预设未经核实的模型名称。

每个三维资产按需生成：

1. 原图观察角度的完整独立对象；
2. 正交正视图；
3. 正交右侧视图；
4. 正交顶视图；
5. 必要时补正交背视图。

每条正交视图提示词必须独立写明：

> 采用严格正交投影，不使用透视相机，不使用三分之四视角或等轴测替代。相机沿该视图对应轴线观察，与对应基准平面垂直，画面无倾斜。平行结构不得出现近大远小或消失点。顶视图必须垂直向下，不得露出由斜俯视产生的建筑立面或底座侧壁。

统一要求，须分别写入每条相关提示词：

- 背景为纯暗紫色，无渐变、场景、地平线与其他摆件；若具体任务接受透明背景，可明确改用透明背景。
- 主体完整，不裁切；被遮挡的承重结构与接地部位合理补全。
- 保持屋顶、门窗、枝干等结构数量与位置一致。
- 使用中性柔光，避免强烈投影掩盖结构。
- 固定对象朝向与比例基准，不为填满画布而分别拉伸各视图。

地表材质例外：

- 生成无透视、无地形侧面、无建筑与动物的平面材质，无须三视图。
- 需要平铺的材质必须检查接缝。
- 不把光照、高光或物体投影画死在基础色中；纯材质区域不混入暗紫色背景。
- 地表贴图不替代坡面、山体、海岸与土层几何。

## 四、阶段三：生成并检查辅助视图

先完成一个代表资产，再批量处理同类资产。

每组任务先生成原角度完整提取图；检查通过后，以该图及原始参考为依据生成其他视图。各视图均参照同一组基准，不以上一张派生视图作为唯一参考，避免逐步漂移。

需要并行时，按实际可用并发能力分批处理，每个工作单元只负责一个资产组，不同时改写共享文件。

逐张检查：

- 投影和观察方向是否正确；
- 结构数量、相对位置与比例是否一致；
- 遮挡补全是否合理；
- 是否出现悬空、融化、重复部件或新增装饰；
- 顶视图是否错误露出侧面；
- 右侧图是否误画为左侧或斜视图。

存在问题时修订提示词并重生成，记录版本和原因。无法消除的多视图矛盾须明确记录，交由统一灰模解决，不能声称已达到工程正交精度。

## 五、阶段四：建模、材质与游戏内验证

### 1. 先完成灰模与结构对齐

使用 Blender 建立真实三维模型。

先锁定外轮廓、占地、比例、主要高差和组件位置，再增加细节。保持主要结构可辨识，避免以大量随机小几何代替参考图中的明确形态。

从同一个灰模渲染正交正视、右侧、顶视与背视图，作为后续唯一的结构基准。对生成参考中的矛盾逐项说明取舍。

### 2. 按功能拆分模块

地形按需要拆为底座、连续地表、边缘过渡、植被、动物与局部生产设施。

薄玉牌、玩家配色区和未来需要动画的部件独立保留。树木与麦穗预留根部固定和风动信息；动物预留适合动作的结构；活动工具设置正确枢轴。

重复对象使用共享模型及有限变体，控制整桌重复感和渲染成本。单位、轴向、缩放、枢轴、水线与交互碰撞按项目美术规范及现有工程核对。

### 3. 几何与材质要求

- 所有游戏可见方向完整，360度观察自然。
- 布线有序、适合目标结构与动画，避免无意义的细分及细长退化面。
- 关键轮廓采用真实几何，小尺度细节按观察距离采用贴图或法线。
- 硬质边缘适度倒角，避免所有边缘使用同样夸张的圆角。
- 无明显破洞、错误法线、悬空、穿模及重合面闪烁。
- 门窗能够看入的范围制作必要厚度和可见内部；不制作镜头无法观察的完整室内。
- 植被允许使用经过检查的薄片与镂空材质，不把实体封闭要求机械套用到草叶。
- UV 密度依据实际模型尺寸与游戏观察距离统一，防止纹理拉伸、明显重复及远景闪烁。
- 基础色保持材质本色，法线优先从几何或经验证的高度信息烘焙。
- 检查 Unity 中的法线方向、色彩空间、透明裁切、阴影与材质效果。

### 4. 面数与性能预算

每类资产分别记录 LOD 三角形数、材质槽、贴图尺寸与预计同屏实例数量。

6000 tris 可作为单件复杂建筑的初始候选上限，不作为所有资产的统一指标。树、羊、草簇、地块与港口分别分配预算，最终按整桌测量结果调整。

同时记录单资产成本和最大地图总成本。LOD 尽量保留轮廓、色块和主要层次，远处降低细节密度，避免细草混叠。

不能仅凭 Blender 渲染速度、单块截图或不等待 GPU 完成的计时宣称游戏性能达标。

### 5. 对照与验收

输出：

- 同一模型的正交正视、右侧、顶视与背视图；
- 与原型尽量匹配的观察角度；
- 默认游戏镜头和反向镜头；
- 相邻地块拼接及拥挤节点视图；
- Unity 实际运行截图。

分别检查轮廓、高差、色彩、疏密、材质尺度、接地关系、道路净空、玉牌可读性与操作遮挡。

棚拍渲染与游戏截图分别标注。不得用生成图片或后期修图替代真实模型验收。

在最大测试地图验证总成本；Android 没有真机结果时明确标为待验。

### 6. 交付与完成条件

交付源 .blend、可重建脚本及参数、导出模型、纹理、材质配置、LOD、资产清单、预览与检查记录。

保留参考原件和旧版本，处理结果另存版本。沿用 assets/references、assets/prototypes、art/source、art/recipes、art/exports、art/previews 及 Unity 实际运行资源各自的目录职责，记录参考路径、提示词、工具版本与导出参数。

先完成指定样板的真实模型与游戏内闭环，经外观验收后再扩大生产。未通过项逐项列出，不以「成功导出」或「能够显示」代替美术验收。

接入游戏时遵守现有规则与表现边界：使用稳定 Tile／Vertex／Edge ID；装饰不拦截交互，不参与规则结果；表现层只读取当前玩家允许看到的投影，不读取隐藏牌、未揭示地图或权威随机状态。

代码修改、版本递增、构建、日志、阶段退出与提交推送遵循 AGENTS.md；仅编写方案不代表实施或阶段完成。
