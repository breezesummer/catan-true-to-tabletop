
## Unity 与 Windows

执行入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\development\Build-M4.ps1 -VerifyPlayer
```

固定 Unity `6000.3.25f1`、URP `17.3.0`、Windows x64 Mono。构建在 Unity 中实际创建 M4 规则会话并完成权威保存恢复，不以新 .NET 测试成功推断 Unity 兼容。

Windows 驱动器通过实际 `M4App` 方法和同一命令入口执行三人/四人正常开局、开局城市只领资源、强盗初始离板、事件骰、蛮族待决、错误目标原子拒绝、坏存档保留原局、换座清除私有视图和选择、随机继续一致及点边格拾取。保存与恢复在两个不同进程中执行。拾取覆盖默认/俯视及两个缩放级别；没有冒称人工鼠标点击。

最终构建耗时 49.5 秒，保存进程 99.0 秒，恢复进程 6.6 秒，全部成功退出。实际 GPU 为 AMD Radeon RX 9070 XT，Windows 窗口配置 1440×900，相机输出 1440×1080。

- [Unity 构建日志](verification/m4-2026-10-09/unity-build.log)：`CATAN_M4_UNITY_CORE_OK`、`CATAN_M4_UNITY_BUILD_OK`。
- [保存进程日志](verification/m4-2026-10-09/player-save.log)：`CATAN_M4_PLAYER_SAVE_OK`、`CATAN_M4_RENDER_OK`、`CATAN_M4_COMPONENT_PREVIEWS_OK`。
- [恢复进程日志](verification/m4-2026-10-09/player-load.log)：`CATAN_M4_PLAYER_LOAD_OK`、相机和组件渲染标记。

该 Windows 简单席位驱动本次成功执行骑士操作数为 0，不能将其当作骑士行为的 Windows 独立案例；骑士规则执行由 .NET 独立案例和完整对局覆盖，Unity 已编译相关代码并实际渲染各级骑士。三个核心 DLL（.NET 输出、Unity 插件、Windows 程序依赖）SHA-256 相同，确认为同一版本。

Unity 批处理退出日志有 Mono 调试线程清理警告，最终退出码为 0；两个 Windows 进程日志没有运行异常。首次开发构建曾发现验证脚本的 C# 声明语法错误，已修正，最终编译和上述进程均重新执行；不将失败构建作为通过证据。
