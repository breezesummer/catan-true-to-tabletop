表格的“血量3”保留为原始资料；本次采用3轮寿命，不据此增加三国杀式伤害、扣血、濒死或死亡系统。

## 二、建议的实现方向

建议先把三国扩展接入城市与骑士核心，以同一套武将处理器接入双扩展组合。先实现选将、轮换、阶段与可恢复的技能结算，再分批补齐武将；每批都保留可从正常开局玩到结束的版本。

54张武将不能全部做成“点击按钮后增减资源”。它们改变了谁可以行动、谁能看牌、何时生产、怎样定义牌、地图连接关系和胜利归属。工程重点是把这些变化集中到有限的公共机制，再给每个技能写明确处理器。暂不建设任意脚本解释器，也不让卡面文字直接执行规则。

模式开关建议采用版本化的三国规则配置，记录武将包版本、内容哈希与支持的剧本。未完成的武将只出现在明确标注的开发测试包；不能在正式标为“完整三国包”的对局里悄悄禁用某些技能。

### 1. 武将与玩家持有效果分开保存

建议新增 `ThreeKingdoms/` 纯C#目录。下列名称是拟新增类型，非当前工程已有接口。

| 对象 | 需要记录的内容 |
| --- | --- |
| 武将定义 `GeneralDefinition` | 稳定定义ID、名称、称号、势力、技能列表、原文、确认后的规则版本、原表单元格 |
| 武将牌实例 `GeneralInstance` | 本局实体ID、所在区域、所属玩家、当前任次、公开状态；同名不同牌不合并 |
| 登场任次 `GeneralTenure` | 登场轮、剩余寿命、当前技能、限定次数、标记、循环指针；重抽登场创建新任次 |
| 玩家效果 `PlayerEffect` | 来源武将与任次、持续到期条件、整局／一次残留、是否可叠加、是否已消耗 |
| 轮换状态 `GeneralDraftState` | 同批选择ID、每位玩家私密候选／独立决策ID／提交状态、必须选择数量、弃选回库、统一公开屏障、补将后待登场选择 |
| 武将牌库状态 | 公共库、隐退库、候选、在场、暗置及技能留置各区的稳定实体ID，耗尽回收批次及权威抽取记录 |

身份不要只使用姓名。神甘宁和吴甘宁是两个定义；同一实体回池重抽需要保留牌的身份、另开新任次，才能既重置新任次又正确追溯旧残留效果。

“留在面前不回池”与“进入隐退库但保留一次效果”是不同状态。关羽、华雄、庞统的留置，曹操／贾诩的残留，以及华佗的整局保护，都需要显式记录，不依赖武将牌当前在哪个UI面板。

B4抽将按以下顺序处理：从公共库逐张无放回抽取；一次请求尚未抽足且公共库已为0时，才把隐退库中全部可回收牌移入公共库，再继续抽取。比如需2张而公共库仅1张，先抽走该1张，再回收并抽第2张；不能因“不足2张”提前混回。沿用稳定ID排序和权威随机索引抽取，单纯移区不额外洗牌或耗随机。当前候选、在场、暗置及技能留置牌均不可回收；未选候选直接回公共库，不经隐退库。两库确实不足时，轮换沿用B0的异常短缺兜底：仅1张则发1选1，完全无牌则从原暗置登场；没有可登场武将的异常状态保留诊断并拒绝继续，不能造牌。该兜底不适用于正常开局。

开局先锁定整批候选，再同时开放各人的选择，不依赖先提交者退回的牌给后提交者补发。所需不同实体数为`4(n−1)+5=4n+1`，三人至少13张、四人至少17张；当前B3的16将包只能满足新的三人门槛，B4须至少再完整实现1张武将才能开放四人新规则。轮末多人同时到期也按同批处理：先快照到期名单并完成移区，按固定座位分配全部补将候选，再并行选择、统一公开；技能结算仍按既定顺序。单人主动隐退只建立该人的补将待决，不等待无关玩家。

### 2. 正常轮与回合必须分开

现有 `GameState.Turn` 在玩家结束回合时递增，初始摆放为0、摆完为1。它不能直接用于计算3轮寿命，也不能用 `Turn % 玩家数` 代替正常轮：额外回合和换座都会使这种算法失真。

建议保留旧Turn语义，新增正常轮序号、固定座位游标、回合实例ID、回合来源、阶段和窗口ID。翻面跳过正常回合时，消费该座位行动机会并翻回；不进入各正常阶段。换座只改变座位上的玩家，不用“本轮已经行动的玩家集合”抵消换座造成的重复／遗漏行动。额外回合另建实例且不推进正常座位游标；跳过边界与到期清理依百科G12建议。

中途登场计当轮，可用“该任次在每个计寿轮末最多减一次”表达。换座不改轮界、额外回合不计轮已经确认；本轮建议在正常游标回1号位之前结算旧轮寿命及已排额外回合，轮界新将从下一轮起计。到期名单须快照化，不能让补入的新将再次被本次扣减。

阶段顺序为准备、判定、掷骰、弃牌（条件出现）、摸牌、出牌、结束；用户G05追加“掷骰阶段后，就是摸牌阶段”。B0已将弃牌定为有来源的可插入子阶段，七点弃牌在本次骰点结算后、摸牌前完成；其他弃牌返回精确父步骤。每个真实回合只有一个全员摸牌阶段，零产出／7仍保留，不为每个领取者重复触发阶段技能。B4改变推进方式，保留这些结算顺序。

B4由纯规则调度器推进准备、判定、掷骰、摸牌和收尾：进入时机后收集技能，处理强制效果和可选询问，完成子效果后继续父流程，直到出现真实待决、进入自由出牌或终局。正常投掷由流程触发，改骰、候选及重掷仍按技能等待选择；七点弃牌、金矿和回合外响应必须处理完再前进。玩家结束出牌后，结束技能、期限、额外机会、寿命及下一行动机会由系统接续，无须额外阶段确认。

自由出牌不能因当前没有必选项就自动结束，也不能因提示收起或网络暂断而视作放弃。主动隐退入口保留，可提交在下一合法边界执行的意图，并可在允许的待决窗口插入；自动推进与该意图由权威入口排序，原子提交不被拆开。B4规则定稿须明确准备／判定等自动经过阶段的预设换将入口与意图保存、失效规则，验收包含没有技能待决时仍能按意图在指定合法边界换将。交互不能要求玩家在动画或一闪而过的阶段提示中抢点才能换将。

### 3. 使用可恢复的效果步骤

建议每个技能拆成若干可保存步骤：校验时机和目标、确定费用、支付、选择／响应、执行、结算后触发、继续父流程。具体先后、支付能否被中断、目标无效是否退款由用户规则决定。

`EffectFrame` 至少包含效果ID、源技能、源任次、根事件、父效果、控制者、资产拥有者、目标、当前步骤、已支付费用、当前待决和后续步骤。`DecisionId` 与 `WindowId` 一起校验，旧窗口的“确认”不能用于新窗口。

当前 `DecisionQueue` 可以借用其“等待玩家选择后继续”的思路，但不能把多个嵌套效果都写入唯一 `ReturnPhase`。每个父效果都有自己的恢复位置。本轮参考无名杀后建议父子效果帧、按座次排序的触发队列和恢复栈配合：子效果先完成再回父效果，同级已排效果保持规则顺序，不能因为使用栈就颠倒多个额外回合。

现有公开 `GameEvent` 与命令回执有数量关系，不能直接把每个技能子事件都追加进去。建议新增内部规则事件流，原命令回执仍按现有合同处理，最终再投影成适合玩家阅读的历史。

B4将触发检查接入阶段、正式骰局、得失牌、目标及结算后事件。可选技能自动建立“是否发动”的待决，确认后选择费用／目标并原子提交；不需要选择的强制技能直接执行。出牌阶段的主动技能在首次满足时机时提示，之后保留可用入口，不在每次刷新时反复弹窗，也不自动循环发动可重复技能。按事件、技能、任次及窗口记录已询问／已响应状态；放弃只关闭本次机会，不消耗发动次数或费用，新独立事件仍可再次触发。读档、重连及重复快照恢复已有待决，不重新询问已处理机会。

### 4. 资源和虚拟牌按不同维度处理

每次牌移动记录实体牌种、有效用途、来源区、目标区、原因、数量、批次与父效果。资源／商品仍可用计数袋保存，不必为了技能给每张普通资源卡都生成对象；需要隐藏抽取、临时亮出或跟踪具体选中牌时再使用临时牌集合。

赵云用砖当木头支付时，规则校验读取有效用途，库存处理必须仍能追溯实体砖。如何回银行、交易接收者得到什么、曹植按哪个类型收牌，属于G15/W42等待确认规则，不能只改资源名称了事。

视为发展卡需要独立的虚拟用牌上下文：不默认从真实牌堆扣一张，也不默认能被曹操变成一张实体卡；这两点由逐将确认决定。费用中途不直接触发递归回调，先按确认的单张／批次粒度发事件，再由调度器处理。

随机资源、商品混池、抽验退回及短缺已在百科G08／W42给出首轮建议：按当前真实存量加权，临时区不算手牌，实际获得才触发。实施前将采纳的概率与不足规则写入版本化规范。随机取牌只消耗权威随机状态，预览不能提前抽样。

### 5. 骰子结果分为尝试与最终结果

建议为每次投掷记录用途：正常生产、延时判定、技能判定、比大小；以及原始值、候选值、选择值、修正、最终值、事件骰和是否执行正常生产。

鬼才已明确只改一颗数字骰且直接匹配不大于6的地产数字。甄姬重掷、诸葛亮二选一、周处加3、指定黑7，需要共同经过一个结果提交入口。哪些试投会触发集智／勤政／屯田等，哪些只看最终结果，必须确认；不能因为动画掷了两次就自动结算两次入侵。

判定复用骰子并不等于复用整段正常掷骰逻辑。用户明确判定不产生常规资源；实现中使用用途标记阻止常规生产，技能明示的判定收益单独结算。B3已按[B3规则定稿](three-kingdoms/B3规则定稿.md)落实独立基础：判定／比大小只投两颗数字骰，不投事件骰、不执行普通产出、发展牌发放或入侵；正式骰局、鬼才、观星及直谏已接城市骑士和组合宿主。重掷只保留独立候选基础，未启用甄姬。

B3五将没有判定或比大小的来源技能。实际来源以后调用`BeginJudgment`、取得`TakeFinal`结果并更新宿主最终数字，再以`OnDiceResolved(..., formalRoll: false)`通知勤政等允许的观察者，最后恢复来源效果。此来源接续属于B4等后批工作；B3的判定基础测试不能表述为“判定触发勤政的正常宿主技能已完成”。D05的确定预期与验证分工见B3规范第8节。

### 6. 损害模型不能只增减建筑数组

至少区分拆除并归还供应、城市降级、村庄倒塌、道路横置、设施扣置、骑士死亡与修复。黄忠BB7定义的具体行为只绑定烈弓；其他武将即使写了“拆除／横置”，也需有自己的已确认处理规则。

修复基础费用已确认为原建筑费用，恢复正常状态。城市从村庄恢复是否收城市升级费、道路两种损害是否都可修、设施扣置是否属于修复对象，仍需细化。华佗原文写“一张牌修复”，这一张牌是否替代全部常规修复费用、能否修复已离场的道路或死亡骑士，统一保留为W54待确认项。

建设与损害完成后，要重新计算生产能力、合法落点、连通、最长道路／航线、科技能力、大都会和分数。免费建设仍需经过同一合法性入口；哪些前置条件可以被技能豁免必须显式列出。

### 7. 鲁肃地图变更采用完整事务

建议保留空间Tile／Vertex／Edge ID，区分“地图位置”和“板块内容”；交换地形、数字与已确认要随行的附着物，不给整个棋盘重新编号。孤立建筑归属、共用顶点、跨板块道路等先做书面例图确认，再写变换算法。

先在事务副本上生成两块板块及0至5次顺时针旋转的候选状态，逐个检查放置、资源类型、港口、海陆邻接、骑士、强盗海盗及剧本标记。工程上建议在确认合法候选后才提交操作；没有合法候选时不消耗限定次数是待用户确认的规则建议，费用与次数的实际扣除时点按最终规则处理。

港口最近位置并列、已有登岛分是否扣回、迷雾内容能否交换、特殊中立建筑和奇观能否移动，均未定案。九图组合应建立逐图能力表，不能以普通地图交换通过代替九图验收。

### 8. 钟会与貂蝉需要独立权限设计

区分玩家身份、座位、当前回合拥有者、输入命令者、临时控制者、资产拥有者与联盟。貂蝉操控回合不能通过交换账号身份实现。司马师换座涉及行动顺序、颜色和资产的哪些变化仍待G17/W48确认；建议固定账号与玩家身份，并将用户最终确认的其他变化作为显式状态变更记录。

钟会的共享科技、港口、骑士与共同胜利是新规则体系。建议通过关系查询计算可用能力，保留棋子实体所有者，避免共享骑士被复制到两人库存或同次入侵重复计分。联盟人数、条件协商、退出和隐退后期限、胜利算法均要先确认。

共同胜利还涉及终局检查点、获胜者集合和界面文案。当前M4／M5在Execute后及部分事件过程中检查胜利，终局会清空待决；普通结果用 `WinnerPlayerId` 表示，M5仅为剧本特例保存 `ScenarioState.WinnerPlayerIds`。不能把该特例当成已经支持联盟胜利。技能链中何时检查、响应能否改变结果、胜利后停止哪些效果，应先确认再改造 `CheckVictory`、`FinishSpecialGame` 和房间完局判断，避免提前截断结算。

若“有条件同意”允许开放式谈判，程序只能提供已确认且可执行的条件选项或把口头约定显示为非系统保证。不能擅自替用户选择债务、资源转让、未来承诺等合同类型。

## 五、交互、存档、联机和AI

### 玩家界面（2026-10-24修订）

开局所有玩家同时进入各自的私密候选面板，明确“选2张”与“选择登场”；轮换面板明确“必须留1张”以及接下来可登场的武将。同批全员提交后才统一公开登场。其他玩家只看到允许公开的完成进度，不显示候选、暗置或提前提交的拟登场选择；公共库与隐退库分别显示区域与数量，牌序保持隐藏。单机同屏换座可依次录入私密选择，但规则仍先分配整批候选，按同一屏障统一公开，不退回串行发牌模型。

开局使用底部临时候选牌带，明确“选2张”与“选择登场”；轮换沿用该牌带，明确“必须留1张”以及接下来可登场的武将。保留B4各席独立选将及全员统一公开。其他玩家只看到允许公开的进度和登场将，不显示候选名单。

桌面提供当前将、寿命、技能次数、标记与持续效果详情。提前隐退在自己回合的已确认合法窗口提供入口，不限次数；连续换将由玩家主动选择，不自动替玩家抽换到某个目标将。

常规技能、费用、弃牌和目标选择不再弹出大窗口。移除顶部三国横条及“武将与技能”遮罩面板，把轮次和阶段并入紧凑状态区，把实际待决放在手牌上方的单行操作条。直接点本人手牌、玩家头像、场上建筑或合法落点完成选择；只有没有桌面对应物的私密候选、猜牌类型等使用局部临时候选带。强制待决不能通过收起、取消草稿或点击空白绕过。详细交互与取消边界见第十节。

B4自动弹出当前有权响应者的技能询问，显示武将名、技能名、触发原因与“发动／放弃”；其他人看到等待提示。阶段条只展示当前进度与暂停原因，删除“推进当前阶段”和各阶段“完成”按钮；出牌阶段保留结束出牌／回合入口。强制技能没有可跳过规则的“放弃”，需要资源或目标时仍打开选择界面。

**资源相关选择统一用牌面。** 复用[金矿资源选择](verification/card-action-flow-1.6.13/金矿资源选择.png)的选牌方式及[现有资源牌自适应布局](verification/trade-window-style-1.6.13/README.md)，覆盖资源／商品领取、支付、弃置、赠予、换牌、公开亮牌挑选、指定或声明牌种；技能文字按钮与文字数量输入不能代替牌面。显示实际资源／商品卡图、可选数量、已选数量、选择上限、选中态和按规则禁用的原因，点击／触控选牌后一次确认批次。指定牌种类操作不一律按银行库存禁用；库存仅在该动作确实取牌或付牌时参与资格校验。资源转换同时标明真实支付牌与有效用途；无权查看的随机取牌使用牌背，不暴露牌种。名称和说明仍可作为辅助文字。

涉及地图交换和摧毁时先显示最终规则预览和受影响棋子，再确认命令。预览不消耗随机、不扣费用和次数。Windows与Android使用同一完整桌面布局，按项目已确认方向适配触控，不另造不同规则的手机简化版。

左侧棋子上移，其下放武将牌占位框，框边放技能按钮；右侧为左对齐、卡边相贴的手牌，最右为“资源卡／发展卡／整理手牌”。主动技能合法时可左击，被动技能不可左击；两者都可右击查看说明。武将先用带姓名、寿命和状态的框占位，后续美术按[美术规范](ART_PIPELINE.md)保存原件与版本化加工结果。

### 技能历史记录

B4必须为实际发动的技能生成可读历史，覆盖主动、强制、可选及回合外技能。每条关联事件／效果ID、玩家、武将任次和技能ID，展示玩家名、武将名、技能名及规则允许公开的目标和结果；例如“玩家甲发动刘备【仁德】，向玩家乙交给2张牌”，牌种仅在规则允许的观察者记录中显示。不能只写“完成武将技能选择”。

以权威接受发动／提交效果的记录为依据，同一技能的一组多步选择、重复命令、读档、重连与历史分页不能重复产生“发动”记录；同一技能的新合法发动仍单独记录。放弃、预览、非法请求不记作发动，已成功发动但被免疫或后续失效则如实记录结果。自动触发及后续牌流通过来源关联，不能仅靠UI按钮点击推断。历史投影遵守隐藏信息权限，不写未公开的候选、暗置、手牌、声明真值或牌库次序。

### 权威存档与版本

必须保存规则版本、场景版本、武将包版本与哈希、全部武将区域（含独立隐退库）、当前任次、寿命、限定次数、标记、持有效果、正常轮行动机会、额外回合、控制权、完整效果步骤、自动推进游标、技能已询问／已响应状态、同批各人私密待决与提交状态、随机状态、历史事件身份与命令去重回执。

当前M4保存格式为4、M5为5，两者的Load都会按InitialSeed重建并逐条重放ProcessedCommands，最终对比权威状态。因此新增抽将会改变随机消耗；不能把三国规则套进旧规则版本后继续使用同一重放解释。新规则需版本化，旧存档继续走旧规则，跨版本迁移只能作为显式且有测试的工作。

B4为自动推进、同时选将和隐退回收建立新的规则／武将包版本。B1–B3存档保持原串行、回池和阶段命令解释，不能载入后静默替换为B4；新局才采用本次合同。自动步骤必须由权威规则执行和保存，客户端刷新、动画完成或AI额外发送“推进阶段”不能成为推进的必要条件。

可继续使用一个权威随机源；也可给抽将与骰子拆分确定性随机流，但后者属于需要版本化的工程决策。无论选择哪种，算法、状态、消耗次序必须保存，动画和AI不能另外调用随机数改变游戏结果。

### 隐私和协议

当前 `GetPlayerView` 会复制PendingDecision，不能直接把私密候选塞入公共Options。建议分离权威待决和观察者可见待决，对非决策者只返回“某玩家正在选将”。技能错误信息、合法动作列表、回放、历史和动画同样不能泄露暗置将。

B4用同批多个独立待决表达同时选将，每人只获取和提交自己的候选。服务端串行原子接受命令不等于玩家必须按座次等待：已提交一人的选择不能使其他人的有效DecisionId／WindowId过期，也不能改变其已锁定候选。同批完成屏障、乱序／重复提交、断线AI接管和重连均须保持这一合同。

AI已有资源／商品和发展卡颜色数量的专用权限，不代表获准知道暗置将、候选或武将牌堆。新私密字段按新规则分别授权。看牌、貂蝉操控、明牌状态使用有来源和期限的查看授权，结束后停止后续信息流；不能假设人类会忘记已经看到的牌。

网络当前协议版本为3，WireJson使用严格类型白名单。新增命令、响应字段和枚举须同步客户端、服务器与测试，旧枚举数值不得移位。是否升级协议号按具体兼容改动决定；房间必须检查武将规则版本和内容哈希，拒绝不兼容客户端。

### AI及自动推进

每种待决都需要一个能合法完成或合法放弃的AI动作，包括发将必须选1、强制弃牌、多人质疑、虚拟入侵和地图目标。先保证不会卡死，再评价选将、combo与敌我策略质量。

B4的阶段推进属于规则调度职责，AI只负责自己有权作出的选择；真人、AI和房间服务使用同一流程。并行选将时逐个调度尚未提交的AI席位，不能只查看当前回合所有者。技能响应、选牌与换将后自动续步，不依赖客户端轮询发送阶段命令；保留有界、脱敏诊断，避免无界自动链、主线程长时间阻塞及每个内部步骤广播一次全量状态。

连续换将不限次数是已确认玩法，AI可以基于可见收益决定停止，但不能在规则层给人类偷偷加次数上限。测试驱动器可设运行预算用于发现持续循环，并报告轨迹；预算耗尽不能宣布正常获胜或修改正式规则。

断线AI与重连复用现有房间生命周期。需要额外验证当前回合玩家并非当前响应者、貂蝉临时操控、翻面跳过与额外回合时，恢复的是正确操作者及正确决策。

### 9.2 建议采用的具体结算合同

一个动作建议依次走：合法性预检、锁定费用／目标、原子提交费用、费用触发窗口、目标确认窗口、逐段效果与免疫、牌去向及分值归属、结果触发、返回父流程。明确的时机替代可改变其中某一步；交易和多牌支付不得被切成半次成交。主动取消只能发生在尚未付费的允许取消点；已经付费后目标无效通常只令后续无效果，不能撤销已发生的响应。

建议保存的最小信息包括：

- 效果帧：效果／父效果／根事件ID、来源武将任次、技能ID、回合和阶段ID、操作者／资产所有者、目标、步骤、已付费用、已完成分支。
- 窗口：窗口ID、当时座次快照、待处理与已处理候选、优先权位置、强制或可选、当前决策及授权人；换将后旧窗口不能重放。
- 牌移动：真实类型与有效用途、原区／目标区、原因、批次、实际数量、临时区归属；需要按具体实体追踪的牌用稳定实例ID或等价可追溯记录。
- 持续效果：来源、期限、叠加规则、是否随在场消失；玩家永久效果与武将任次标记分开。
- 骰子：用途、尝试序号、候选、单骰改点、合计修正、最终提交状态；预览零随机消耗。
- 系统状态：固定座位游标、额外回合队列、寿命扣减名单、规则／场景版本、权威随机状态、命令去重回执和私密投影权限。

例：吕蒙受乱击影响，先在抵御窗口选择石头并一次支付；该次失牌触发的屯田等子效果完成后，返回乱击的下一名玩家；若回合所有者在允许窗口换将，先完成换将子树，再重验余下选择。不把下一名玩家的抵御请求覆盖在上一个判定的唯一PendingDecision上。

### 9.3 循环与验证边界

免费无限换将及重抽重置是已确认玩法，允许玩家连续主动选择；系统去重只阻止同一命令或同一事件重复执行，不能限制合法的新任次。资源、棋子库存有限并不代表这种策略没有刷取价值。仁德往返赠牌、苦肉拆建、问计无限索牌同样是明确需要试玩的平衡问题。

自动链采用实际数量检查、来源排除、事件候选去重，以及结姻／先辅同一因果沿同一关系只传播一次的明确建议规则；不能简单写“一个根事件里所有技能各触发一次”，否则会吞掉合法独立得失。若仍出现无选择的无限链，应在开发验证中保留轨迹并修规则，不把最大栈深或AI步数预算伪装成正常结算结果。

后续实施至少增加：双技能同层选序；付费后换将继续；旧待决过期拒绝；陆逊批量失最后牌；马良非自身来源再获牌；固政／落英争同牌；鬼才改候选而生产只一次；酒诗翻面额外回合；座位互换跨轮；临时控制权限回收；1分牌奸雄转移后胜利；鲁肃整事务失败不扣次数。每个选择点保存恢复应与连续执行完全一致。以上是测试设计，不是本轮已经通过的运行结果。

### 10.3 技能按钮和触发时机

**用户追加明确：玩家自己出牌阶段的技能全部由玩家自行操作。进入出牌阶段不弹“是否发动”，不强制先处理技能，不按系统顺序逐项询问；玩家可以自由选时机、选顺序，或完全不用技能直接结束出牌。** 系统只更新技能是否可用、费用与剩余次数。此约束适用于自由出牌阶段的主动技能；实际动作产生的规则事件仍按对应的强制／可选触发合同处理，不能伪装成主动提示重新插回开阶段。

| 类型 | 按钮行为 | 触发与等待方式 |
| --- | --- | --- |
| 出牌阶段主动技 | 合法时左击进入草稿；非法时置灰，说明原因；右击看描述 | 完全由玩家发起；不用不提示、不阻塞结束出牌，也不预先消耗次数 |
| 仅在短暂时机可用的主动技 | 时机存在才点亮，左击进入草稿 | 在对应真实时机保留底部窗口，列可用入口和“继续／放弃本次机会”；不自动跨过回合开始、改骰等机会，不把它们延长到整个出牌阶段 |
| 强制且无选择的被动效果 | 被动按钮不可左击；触发时短暂高亮 | 权威自动结算，显示简短结果和历史，不要“确定／知道了” |
| 强制但要选对象／支付的触发效果 | 被动按钮仍不可左击 | 操作条直接显示真实待选内容，点牌／头像／棋盘对象；不能放弃义务，不先问是否发动 |
| 可选触发效果 | 被动按钮仍不可左击 | 在事件发生时进入可取消的选择上下文，直接选牌／目标后确认即表示响应；无额外选择时只留“发动／放弃”两个行内操作。点击的是响应操作条，不是被动技能按钮 |
| 常驻修正、免疫或持续状态 | 被动按钮不可左击，可右击查看状态和来源 | 无选择时只改变合法性或结果，不制造额外待决 |

主动和被动按钮均支持右击显示锚定在按钮旁的说明卡，包含技能原文、时机、费用、次数、当前状态及公开范围内的不可用原因。右击只看说明，不能同时清空选择或提交。Android以长按查看；长按后松手不再触发左击，滑动取消长按判定。说明可收起且不改变任何权威状态。

可选触发默认仍保留选择权，不因为`frequent`、无费用或“看上去有利”就自动发动。下一阶段不新增全局自动接受、自动拒绝或超时默认选择；现有断线AI接管按原规则运行。同层多个触发只有规则允许本人选序时才在操作条提供顺序项，选一项便进入实际选择，不加一层“确认发动”。多个玩家依原规则获得响应权；无权响应者只能看公开等待状态。

### 10.4 统一选择流程

基本路径为：**点主动技能或进入真实响应 → 直接点牌／目标 → 一次确认 → 权威结算**。系统不再先问一次“是否发动”，再开一个目标列表窗口，最后再问一次确认。

1. 进入选择时，操作条写清“要选什么、选几项、用途是什么”。可选手牌、头像、建筑和落点用一致描边；已选上抬或高亮。颜色之外保留勾选、计数和目标序号，避免只靠颜色辨认。
2. 点本人手牌选费用、赠送或弃置的实体牌；普通可用发展牌也可直接点牌进入原卡用途。技能上下文中的点击优先解释为该技能的选牌，不误当普通出牌。转换用途在该牌上方给出短选项，条内同时显示“真实牌→有效用途”，真实牌不被换成虚拟实体。
3. 点头像选择玩家；单目标点击另一合法头像即替换，多目标再次点击移除。依次选择者显示1、2、3顺序标记，付款人、受赠人等不同角色明确标注；点击自己仅在技能允许时合法。
4. 点场上建筑、骑士、道路、船或高亮地块／顶点／边选择棋盘对象。对象映射稳定ID；空白处不猜目标。邻近对象优先通过高亮和悬停描边定位，确有重叠时在原位置展开小型候选标记，不回到全屏列表。
5. 每次增减牌或目标都重算可选集合、数量、费用和确认状态；改动上游条件后，移除失效的下游选择并说明。牌和目标可交换选择顺序的技能允许先选任何一侧；存在依赖或私密揭示的多步技能仍按合同逐步进行。
6. 确认按钮只在完整合法时启用，摘要列出实际费用与目标；一个已发起的普通动作只保留这一次提交确认，不叠加“确定吗”。强制无选择效果自动结算；主动无费用无目标技能仍用操作条一次确认防误触。涉及永久损害的预览纳入同一个确认步骤。
7. 点击取消或Esc撤销尚未提交的草稿；可选响应另有明确“放弃本次”操作。强制待决的“重选”只清空已选对象，不能结束待决。右击对象统一保留说明，不兼作取消；点击棋盘空白不自动放弃。

操作中的局部说明和候选带只拦截自身区域点击；其余棋盘仍可观察、缩放和移动。选择期间原建造／普通出牌入口按上下文隔离，防止同一次点击既选目标又建造；拖动镜头、滑动手牌不得被算作点击提交。

### 10.6 草稿、提交边界和触发恢复

客户端草稿建议由统一的`SelectionContext`管理：技能／来源、操作者／资产所有者、步骤、选牌数量、目标角色、数量范围、窗口和决策令牌、取消权限、确认摘要。此名称为拟新增接口；不允许UI读取完整权威状态自行推导隐藏目标。

- 规则投影提供授权候选与限制；已有`SkillActions`可先适配为结构化选择合同，但不能靠解析中文按钮标签或牌文识别目标。预览和提交仍共用原权威校验，本地玩家、AI和远端玩家不分叉。
- 资源／商品当前按种类和数量保存，UI按牌种与显示序号选取，提交归并为真实数量／用途矩阵；序号不能冒充永久实体ID。已有实体发展牌用稳定实例ID；排序后绑定不能漂移，权威数量变化则重验草稿。
- 选中不等于已发动。纯草稿不扣牌、次数或随机；提交成功后才进入该技能规定的成本阶段。**魄袭例外必须显式展示：提交目标进入私密选牌即占用次数**，以后清空或取消UI草稿不能退回该次数或已获得的信息。类似多步技能按合同标出首次不可撤销点。
- 已付费用和已结算子效果不能因为关闭说明、收起候选带、目标后来无效或网络报错自动退款。保留父效果恢复位置、实际移动批次和已处理候选；子响应完成后重验原目标再继续。
- 普通未提交草稿可在读档／重连后重选；权威待决、已提交费用、牌流、随机状态、响应顺序和可选效果的放弃记录必须准确恢复。不能把未提交的UI选中态当成权威完成状态。
- 同一命令重试幂等；提交期间禁用重复确认。响应令牌过期则作废旧草稿并拉取当前本人投影；暂时未收到回执不直接当作失败重发新命令。沿用B4同时选将的本人令牌例外，不把别人的提交一律解释为本席选择失效。

重点改造`B4AutomationEngine.Offer`：**自由出牌阶段的主动技能不再生成阻塞式首次提示，也不再要求提交`automation-skip`才能开始正常操作或结束出牌。** 真正的事件响应和短暂时机仍有可保存待决；不能用删除全部自动待决来“解决弹窗”。必须区分技能可用时机、UI提示和规则响应三件事。

这是对已交付B4询问合同的后续改造。实施时为改变自动续步／命令历史解释的部分建立新的兼容身份并同步客户端、服务器与AI；旧B1–B4存档继续按旧包重放。可用新界面呈现旧待决，但不能静默删除旧询问命令或改写已保存历史。只改变排版的部分无需改变牌文。

### 10.8 验收矩阵与退出条件

| 验收项 | 必须观察到的结果 |
| --- | --- |
| 自由出牌不催技能 | 含多个合法主动技进入出牌阶段，没有发动询问、技能队列或强制选择；可先建造、先用任意技能、交错用牌，也可零次技能直接结束；主机会话与联机均验证 |
| 仁德／制衡 | 点技能→直接点本人牌→必要时点目标头像→一次确认，**0次模态弹窗**；撤销选择不付费，重复确认仅执行一次；实际牌数依本项目技能合同 |
| 国色与棋盘目标 | 选真实费用和合法头像，不从文字名单选人；已交付建造／骑士／卡效点棋盘对象和稳定ID一致，不因模型、遮挡或镜头移动选错，不借此宣称B5损害技能完成 |
| 被动与响应 | 被动按钮左击无行为、右击／长按有说明；强制无选择效果0次点击，强制有选择不能跳过；可选响应在操作条可完成或放弃，拒绝不会重复弹回 |
| 时机与顺序 | 回合开始、骰子修改、回合外响应不会被自动推进漏掉；同层选序、嵌套子效果和返回原步骤保持规则结果，无选择的链不会卡在UI |
| 多步与隐私 | 魄袭进入私密选择后的次数不被取消退款；于吉多人承诺与验真、分堆、同时选将保留授权和公开屏障；他人看不到草稿、隐藏候选、真实底牌或牌库次序 |
| 手牌布局与动画 | 空手、1张、少量、超量、多牌类时均固定左对齐且无正间隙；排序／切标签不换选中对象；收牌、支付、悬停、滚动与选中上抬没有旧坐标残影或点击穿透 |
| 输入与恢复 | PC右键、Esc、重复点击；Android长按、松手、滑动、返回操作；本人非回合玩家响应、断线AI接管与重连都回到正确决策，不重复付费、不丢强制待决 |
| 兼容与回归 | 新旧包存档精确恢复、同随机状态同命令结果一致；所有失败命令和预览零变更；资源／棋子守恒；原模式既有失败与基线逐项区分，无新增失败 |

退出时提供覆盖30将51技能及全部待决类型的映射与测试结果；城市骑士和九图组合的3／4人20种正常配置完成自动完整局回归，并记录技能覆盖缺口，不能用完整局代替具名案例。对改动的自动时机补独立正常、非法和状态不变量测试；窗口移除、点击路径和手牌几何需要实际UI证据，不能只靠静态代码断言。

PC鼠标操作、Android真机触控、存档／联机恢复和用户试玩分别登记证据；外网多人和长局性能的既有未验收项继续单列，不借此次布局完成宣称M7／M8退出。上述代表常规流程的模态弹窗计数为0，临时候选带和用户主动打开的说明另行统计；不通过自动替玩家接受可选技能来降低点击数。达到B4.5全部退出条件后再更新完成状态、提交推送代码并开始B5；缺设备或未试玩时如实保持未完成。
