# 按席位同步与恢复合同

适用：联机性能方案第二批 P4、P5。协议版本继续为 3，权威存档格式不变。

## 能力与兼容

新客户端在 WebSocket 建立后主动请求 `Sync`。成功后该连接接收 `Code=SeatStateV1` 的回复，既有 `ViewJson` 字段承载 `SeatStatePacket`，没有给旧严格解码器增加根字段。原 `Get`、`Command`、`Preview`、`History` 及第一批轻量操作保持可用。

旧服务返回 `UnknownOperation` 时，新客户端立即重试原 `Heartbeat`／`Get`，保持请求身份，避免等待下一个 10 秒心跳。旧客户端不会请求 `Sync`，继续接收原全量形状。同一房间允许两种连接并存。

HTTP 的 `Sync` 返回普通完整视图与完整可见历史，使用 `Code=SeatStateSnapshotV1` 标识事件覆盖。它用于增量流中断后的恢复；常态命令回执无需再立即请求完整状态，先等待 WS 推送，500ms 内未满足所需修订才由 HTTP 补齐。

## 提交与推送

房间成功持久化后登记修订与单调时钟；释放房间锁后唤醒该房间订阅。AI、超时托管、连接替换、离开、重开、保存暂停和恢复也通知订阅。拒绝操作不发布虚构的新修订；保存失败只通知回退后的已保存状态与暂停信息。

每条连接最多保留一个待处理唤醒；10ms 窗口合并相邻变更。保留 750ms 周期检查处理遗漏或无修订的在线状态变化。订阅完成立即检查当前状态，连接切换后丢弃旧绑定产生的推送。

投影只复用同一修订、同一席位的数据。投影在房间锁内取得稳定状态，网络发送在锁外进行；不同权限席位的私人数据不复用。

## 状态与事件

| 字段 | 含义 |
| --- | --- |
| `RoomId`、`SeatId`、`ConnectionId`、`RuleSet`、`GameNumber` | 同步作用域；房间、身份或对局变化后不能复用旧基准 |
| `Full`、`FullViewJson` | 首次连接、重开、作用域改变、显式恢复或差量过大时的完整视图 |
| `BaseRevision`、`Revision` | 实际发送基准与本次目标修订；基准必须匹配 |
| `Changes` | 字段或实体数组的增删改；不包含未变化的静态地图 |
| `ViewHash` | 重建后完整可见视图的 SHA-256，用于校验复原结果 |
| `MapVersion` | 该席位可见地块、顶点、边的内容指纹；雾岛揭示按可见变化更新 |
| `EventBaseVersion`、`EventVersion` | 与状态修订独立的事件流版本；版本不连续必须恢复 |
| `EventThroughSequence` | 本次状态已覆盖的完整事件序号范围 |
| `EventUpdatesJson` | 新增或补写的可见事件，客户端按稳定键替换或插入 |

`Changes.Path` 仅穿过对象字段。普通字段的 `Json="null"` 表示设为空值，`Remove=true` 表示删除字段。实体数组使用明确的 `KeyField`／`Key`：地块、顶点、边按 `id`，建筑按 `locationId`，玩家及其他已约定实体按其稳定 ID；`Remove=true` 删除该实体，`Order` 表示最终顺序。未约定稳定键或不能唯一识别的数组整体替换，不凭索引猜测实体身份。

命令历史按命令序号识别，技能历史按 `SkillEventId` 识别。因此同一命令产生的多个技能事件分别保留，同一技能事件的补充结果只替换对应项。事件差量从完整席位可见历史计算，覆盖近期 64 条以外发生的技能补写；普通全量回复的近期历史形状不变。

客户端在后台复原完整逻辑视图，检查作用域、状态基准、事件基准、内容指纹、深度、正文与数组上限，再用原类型白名单、字段、枚举和空值检查完成解码。全部成功后提交该连接的基准，主线程一次切换准备好的视图并合并事件。

## 合并与队列

发送队列只合并尚未发送的完整投影，不直接合并差量。发送器取出最新投影后，相对于实际已发送的状态计算差量和全部事件更新。因此跨过中间快照不会跨过扣费、收牌或技能结果。

命令回执优先并保持顺序；待发送状态只有一份。发送队列另设 8MiB 正文缓冲上限，延迟编码的完整视图与历史也计入预算。饱和或发送超时会结束当前传输，通过原命令编号和完整恢复继续，不静默丢弃回执。单个慢客户端的队列、发送截止时间和同步基准均独立。

成功回执仅证明命令已提交。可见状态、必要历史与展示应用未满足前，客户端继续保留待确认限制。重复、迟到的状态不回退局面；迟到的旧历史分页也不能覆盖事件流已经应用的技能结果。

## 恢复与回退

发现状态或事件缺口、内容错误、切房或连接替换后，放弃当前流的增量基准。正在进行的本地镜头与展示继续使用已确认数据；依赖新状态的提交等待恢复。重新建立 WS 时，每条连接从完整快照开始。

WS 暂时不可用时，HTTP `Sync` 补齐完整状态和事件后恢复操作。仅有同修订的普通 `Get` 不提前结束事件恢复。完整事件超过正文容量时改回原全量状态与从零开始的历史分页，分页结束前保持恢复状态；无游戏视图的等待房间可直接恢复，不等待不存在的游戏历史。

- `--m7-full-state`：本次运行使用原全量同步；先建立新连接、取得完整状态，不把增量缓冲交给旧路径。
- `--m7-legacy-replies`：同时关闭第一批轻量回复与增量协商。
- `--m7-legacy-decoder`：保留原 XML 解码用于诊断。增量在后台复原后，仍按所选解码器校验完整视图。
- 超容量自动回退只影响当前端点会话；切换端点后重新协商。协议与权威存档未变，服务端可切回上一候选版本，客户端自动采用原操作。

Android／IL2CPP 的反射 DTO 由 `link.xml` 显式保留。性能候选包和云端切换、正式发布分别验收，本工作包不自动部署生产服务。
