# v0.1 / M1 固定验收场景

本文件交付 M0-05 的固定验收规格；下方原始结果表保留 M0 时的历史状态。后续 M1 已实施，实际规则测试、Unity 构建与待验项见 [M1 验收记录](../M1_ACCEPTANCE.md)，本规格本身不代表试玩通过。2026-10-08 用户同意先采用官方 2025 规则与明确标注的估算尺寸完成 M0，实体参考后补。实体盒版与尺寸仍未知；规则来源见 [规则基线](../RULES_BASELINE.md)，尺寸见 [v001 估算参数](../../art/recipes/v001/scale-estimates.json)。

权威夹具为 [scenario.json](v0.1/scenario.json)，版本 `m1-fixed-four-seats-v001 / 1.0.0`，规则基线 `catan-base-2025-en-v1`，实际切片规则版本 `catan-m1-slice-v1`。这是一张自编验收地图，不是官方新手固定布局，也不代表完整基础版。更改地形、编号、行动或预期值须创建新场景版本，保留 v001。

## 1. 范围和启动条件

- 固定 19 地块、54 顶点、72 边；4 个本地测试席位，顺时针 P1、P2、P3、P4，P1 固定先手。先手判定和地图随机化由夹具替代。
- 完成 8 组开局定居点与道路、受控产出、一次银行 4:1 交易、一次付费道路建造、结束回合和权威保存恢复。
- 使用同一命令入口处理本地席位与测试驱动器。`RollDice` 不接受玩家指定骰点；受控骰子仅在权威测试配置中注入，不得由 PlayerView 设置或读取。
- 道路、定居点及资源供应有有限数量并核对守恒；本切片没有城市建造、港口、玩家间议价、发展卡、强盗移动、掷 7 弃牌/偷取、奖牌或胜利判定，也没有扩展、AI 产品或联机服务。强盗静置 T10 沙漠。资源短缺分配及各类耗尽边界留给 M2；不得把本例成功称为完整规则验收。
- 切片运行时应明确显示未支持能力。受控队列耗尽时报告测试配置结束，不能循环队列或绕过未实现的 7 规则。

## 2. 标识符、地图与供给

资源固定顺序为 **木、砖、羊毛、谷物、矿石**；JSON ID 为 `wood, brick, wool, wheat, ore`。以下资源向量均按此顺序排列。每种资源初始银行 19 张；每席 15 路、5 定居点、4 城市，手牌为空。发展卡不进入切片；完整实现不得因此把其牌库公开。

地块采用轴坐标 `(q,r)`，范围 `max(abs(q),abs(r),abs(q+r)) <= 2`。按 `(r,q)` 排序编号 T01–T19。整型平面中心为 `(2q+r,3r)`，6 个角按 `(0,-2),(1,-1),(1,1),(0,2),(-1,1),(-1,-1)` 偏移。合并同坐标角点后按 `(y,x)` 排序编号 V01–V54；每个相邻角点对的 ID 升序排列，再对所有唯一端点对排序编号 E01–E72。屏幕朝向可改变，持久 ID 不得重新分配。若要按正六边形绘制，可将平面坐标映射为 `(sqrt(3)/2*x, 1/2*y)` 后整体缩放；这不是毫米实测值。

JSON 显式保存所有地块的角点、顶点坐标与边端点，运行时不能依赖 Unity 场景对象遍历或浮点碰撞结果生成规则 ID。边界共有 30 条边，内部共有 42 条边。

## 4. 首回合、保存与续跑

以下每个成功命令只产生一次状态变化及事件。P2–P4 在首回合均无产出，手牌保持上表值；所有人胜利点仍为 2。除特别注明外，`pendingDecision=null`。

| 命令 / 检查点 | 操作与可见结果 | P1 手牌 | 银行 | 回合、阶段与随机游标 |
| --- | --- | --- | --- | --- |
| C17 / afterRoll | P1 请求掷骰；权威队列给出 2+3=5。T01、T02 各向 V09 发 1 木，共 2 木 | (5,0,0,0,0) | (13,16,17,18,18) | P1 / 1 / Action / 1 |
| C18 / afterTrade | P1 向银行交 4 木，取 1 砖 | (1,1,0,0,0) | (17,15,17,18,18) | P1 / 1 / Action / 1 |
| C19 / afterBuild | P1 建 E65（V46–V50），经 V46 连到 E60；付 1 木+1 砖 | (0,0,0,0,0) | (18,16,17,18,18) | P1 / 1 / Action / 1 |
| C20 / afterEnd | P1 结束回合；P2 等待掷骰 | (0,0,0,0,0) | (18,16,17,18,18) | P2 / 2 / ProductionAwaitRoll / 1 |

C19 后 P1 的道路库存为 12，其他棋子库存不变；棋盘共有 9 路、8 定居点。银行加所有人手牌，每种资源始终合计 19；每席棋盘与库存的路/定居点/城市分别合计 15/5/4。

保存恢复必须实际测试三个时机，比较权威状态的规范化内容，而不是仅看棋盘截图或保存文件存在。可排除文件路径、保存时间等外部元数据，不能排除手牌、随机状态、待决和去重记录：

1. **C07 后待决中保存**：P4 的 V40 定居点存在，E56 尚空；P4 库存 15 路/4 定居点/4 城市，其余席位 14/4/4。所有手牌空、银行各 19，游标 0。待决必须精确恢复为 `{kind:SetupRoad, playerId:P4, anchorVertexId:V40, placementNumber:4}`，阶段 `SetupRoad`。恢复后只能继续合法的 P4 开局道路决策，C08 只放一条路。完整数据见 JSON `pendingSave`。
2. **C17 后保存**：恢复 `afterRoll` 的所有数据；相同 C17 重试不再次产出、不前进随机游标。再执行 C18–C20，与未中断分支逐项相同。
3. **C20 后保存并退出程序再加载**：恢复 `afterEnd`，然后两个分支均提交 C21（P2 掷骰）。下一对骰必须是 1+1=2，只有 P2 的 V15 从 T07 得到 1 谷物；P2 手牌成为 `(0,1,0,2,0)`，银行 `(18,16,17,17,18)`，阶段 P2/2/Action、游标 2。此为 `afterRestoreProbe`，用于证明随机继续位置也恢复。它是切片续跑探针，不是第二个完整回合。

权威存档至少包含：存档格式版本、规则版本及基线 ID、场景版本与内容标识、稳定棋盘 ID/归属、各席完整私有资源和库存、银行、活动玩家/回合/阶段、待决、强盗位置、权威随机算法与完整继续状态、已成功命令 ID 及请求指纹/结果去重资料、事件序列位置。受控队列 `[2,3],[1,1]` 与游标属于权威测试数据，不能进入公开视图、公开日志或发给玩家的同步数据。未知规则/场景/存档版本须明确拒绝，不能悄悄按当前版本解释。

## 5. 非法操作、重试、视图与交互

每个非法案例在所列检查点的独立分支执行，之后恢复主线。使用新的命令 ID，验证拒绝前后的权威游戏状态相同，资源/棋子/待决/游标不变，不新增成功事件。错误诊断可以写独立日志，但不能泄露私有信息。表中理由是产品应表达的错误类别，非强制 C# 枚举名称。

| 编号 | 时机 | 尝试 | 预期拒绝原因 |
| --- | --- | --- | --- |
| N01 | C02 后，轮到 P2 | P2 在 V46 放开局定居点 | 与 P1 的 V42 相邻，违反距离 |
| N02 | C07 后 | P4 开局道路放 E01 | 未连接待决锚点 V40 |
| N03 | afterSetup | P1 结束回合 | 尚未掷骰 |
| N04 | afterRoll | P2 结束回合 | 非活动玩家 |
| N05 | afterRoll | P1 用 3 木换 1 砖 | 切片仅支持 4:1，无港口 |
| N06 | afterTrade | P1 在 E01 造路 | 与自己路网及建筑不连通 |
| N07 | afterTrade | P1 在 E60 造路 | 边已占用 |
| N08 | afterBuild | P1 在 E70（V50–V53）造路 | 位置可连接，但手牌不足 |
| N09 | afterRoll | P1 再请求掷骰 | 本回合已掷骰 |
| N10 | C07 后 | P4 结束回合 | 开局道路待决尚未解决 |

命令重试分别选 C17（产出）、C18（交易）、C19（付费建造），保持 ID、席位和负载完全相同。成功后重复提交，应返回同一已确认结果，不再次产出、扣费、放子、推进游标或重复发布事件；保存加载后同样有效。复用同一 ID 改为不同目标或负载应拒绝冲突。动画取消、跳过、尚未播完或保存加载均不能改变已经提交的规则结果。

玩家权限核查在 `afterRoll` 和 `afterTrade` 进行。P1 的 PlayerView 可含自己的按类型手牌；其他席位只暴露总张数、公开棋子和公开分数，不得有完整按类型手牌字段。P2 的视图不能读取 P1 的资源向量。公共事件可以记录规则允许观察到的产出、交易与建造事实，不能附带所有人的当前完整手牌、牌库顺序、未来骰子、随机状态或未揭示地图。测试断言可读取权威状态，但不能把该测试权限授予 AI 或 UI。即使本例手牌可从操作推知，也必须验证字段级权限边界。

在 UI 中换座先遮蔽私有手牌，再确认当前本地席位；旧席位的详情、悬浮卡和调试面板均应清空。至少检查拿起棋子、合法目标预览、吸附、取消、落下与非法落点退回。拿起/预览/取消不提交规则改变；落下经统一入口确认。相机检查默认视角与俯视、缩放、相邻点选择和山体遮挡；美术样板需按 [美术规范](../ART_PIPELINE.md)从配方重建，不能以生成图片替代网格。
