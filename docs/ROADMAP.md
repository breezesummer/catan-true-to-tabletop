# 开发路线

每个阶段交付一个能启动和检查的版本，并保留上一阶段的可运行基线。先完成本地规则的含义是基础版、两个扩展和组合逐步变得完整；M2 起就可以玩完整的本地对局。

美术从 M1 的样板开始，与后续规则逐步推进。每个扩展先制作规则必需的可辨识组件，再逐步替换为收藏版资产。

| 阶段 | 交付内容 | 完成条件 | 状态 |
| --- | --- | --- | --- |
| M0 项目启动 | 项目约定、工具链、规则基线、素材规格 | .NET 可编译测试；Unity 可导出空 Windows 程序；Blender 可批量生成并导入测试模型；版本记录完整 | 已完成（2026-10-08） |
| M1 本地交互切片 | 固定地图、4 个测试席位、摆放、产出、一次交易和建造、回合及存档；一件立体样板 | 用户能完成预定操作；错误落点无状态变化；存档恢复同一局面；样板脚本可重建 | 待开始 |
| M2 基础版完整 | 基础版所有规则、隐私换座和最低限度规则提示 | 从开局到胜利的完整对局；规则清单逐项验收；关键边界和存档通过测试 | 待开始 |
| M3 航海家 | 船、移动、海盗、金矿、航线、剧本事件与计分 | 先验收代表剧本，再补齐锁定版本的单扩展剧本；资源和供应守恒 | 待开始 |
| M4 城市与骑士 | 商品、城市改良、骑士、蛮族、进步卡、城墙和大都会 | 所有卡牌效果有独立案例；待决选择、攻击与资源结算顺序正确 | 待开始 |
| M5 双扩展组合 | 显式组合规则、场景兼容表、跨海骑士和航线相互作用 | 所有标记为支持的组合剧本本地可玩；组合专项案例通过 | 待开始 |
| M6 本地 AI 对手 | 基础版启发式 AI，再覆盖扩展行动、交易及多步选择 | AI 只读 PlayerView；可合法完成对局；不会因等待选择死锁；记录策略质量缺口 | 待开始 |
| M7 好友联机 | 权威房间、加入、同步、断线恢复、存档继续 | 多个独立客户端完成对局；重试无重复扣费；无越权信息；待决选择可重连恢复 | 待开始 |
| M8 成品体验 | 完整收藏版资产、音效、教程、设置、性能及发布验证 | 清洁环境安装运行；长期对局与目标硬件表现通过；素材和发布条件核实 | 待开始 |

M1 同时验证 Command、PlayerView、Event 与存档接口。早期可以用测试驱动器模拟多个席位、延迟和命令重试；正式的 AI 产品功能与网络服务在 M6、M7 交付。

M0 退出条件已逐项核验，见 [M0 验收记录](M0_ACCEPTANCE.md)。用户于 2026-10-08 确认先采用官方 2025 规则和明确标注的估算尺寸完成 M0，实体参考后补，因此 M0-04 按下表记录开发基线，不声称已确认实体版本或取得实测数据。M1 尚未开始；夹具核对通过不是 M1 游戏功能通过。

每个开发任务包含预期行为、范围、验证方式和结果。实施时优先保持一条主线；可将规则审查、测试案例或独立美术样板并行交给 AI 子任务，合并前检查接口和版本。

规则验证优先使用独立于实现的固定局面与预期结果，并覆盖：资源和棋子供应守恒、非法命令不改变状态、重复命令不重复执行、保存恢复一致、玩家视图不泄露秘密。随机合法行动用于补充探索边界，不替代人工可核对的案例。

Unity 侧检查默认和俯视相机、山体遮挡、相邻节点选取、不同缩放下的标记可读性。性能目标先按指定目标 PC 的 1080p 60 FPS 设置，记录实测硬件后再确定模型与纹理预算。

正式批量制作素材的前置条件是样板通过尺寸、枢轴、材质、相机、拾取与遮挡验证。只在规则、引擎或素材规范有明确收益时调整底层架构，并保留已有存档的版本识别。
