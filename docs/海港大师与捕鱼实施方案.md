# 海港大师与捕鱼实施方案

日期：2026-10-29（Asia/Shanghai）
状态：F0规则定稿已完成，F1—F6尚未实施；最终裁决以[F0规则定稿](harbor-fishing/F0规则定稿.md)为准，不冒充官方规则。
适用项目：卡坦岛之三国争霸。当前版本按 AGENTS.md 为内测版2.1.0；阶段文档中的2.0.2为历史记录。本方案不修改发布版本，不构建、不部署。

## 1. 目标与边界

在现有玩法上增加“海港大师”“捕鱼”两个独立开关，允许同时开启。支持本地人类／AI、局域网、在线房间、Windows与Android共用桌面交互。保持纯C#规则核心、稳定Tile／Vertex／Edge ID及权威命令入口。

首个产品可玩切片：**三国城市骑士标准地图＋海港大师＋捕鱼**。基础规则先独立验证，随后接入三国；完成该切片后再逐图开放航海组合。

本轮不包含商队、河流、蛮族进攻、货车运输等其他《商人与蛮族》内容；不恢复搁置的Ultra计划。现有B7的真机、外网和用户试玩缺口继续保留，不能用本扩展的自动测试替代。

开局选项默认关闭；同房所有人看到一致配置。开始后不可切换；重新开始沿用配置并生成新随机状态；读档使用存档配置。

## 3. 海港大师规则合同

### 3.1 港口分与奖励

1. 统计玩家实际拥有且位于有效港口顶点的建筑；村庄1点、城市2点。同一建筑即使关联多个港口只计一次。
2. 首位达到3点者获得奖励，持有者增加2胜利点。挑战者严格超过持有人才转移，追平不转移。[TB25，第4页]
3. 联盟共享港口贸易能力不共享建筑归属或港口分；奖励不复制给盟友。（项目裁决）
4. 大都会、损坏／修复及三国建筑修正必须明确计数规则。大都会按城市基础2点、附加分不计（官方FAQ）；损坏城市降为有效村庄计1，倒塌村庄计0。F0 D01已锁定，不能依靠总分字段猜测。
5. 建造、升级、降级、移除、归属改变、港口迁移和地图事务完成时重算；持有人跌至3点以下或失去领先后，唯一最高且至少3点者取得，否则奖励回公共区。原持有人仍并列最高且至少3点时保留。（涉及损失的项目裁决）
6. 地图事务和技能结算过程中不逐步触发终局；完成必要响应、奖励重算后，由现有合法胜利窗口检查。不能让地图事务中间状态产生获胜者。

### 3.2 分数设置

采用“开局最终基础目标”和“个人旧靴修正”分离模型：

- 未手动设置时：最终基础目标＝剧本默认目标＋海港大师修正1。
- 手动设置时：输入框表示包含海港大师影响的最终基础目标，不再隐式加1。切换开关仅更新未被手动覆盖的默认值。
- 普通个人门槛＝最终基础目标＋本人持有旧靴时的1。
- 上限校验针对最终基础目标执行；旧靴额外1分允许超出配置上限，不截断。
- `VictoryPointSettings.MaximumForScenario`目前为海盗群岛设13分上限。增加海港奖励后需独立验证可达上限，不能沿用旧上限或统一放开20分。
- 奇观、海盗群岛等额外胜利条件继续由剧本裁决，不用一个统一分数比较替代。

## 4. 捕鱼规则合同

### 4.1 组件与初始化

采用29枚鱼筹码（11枚1鱼、10枚2鱼、8枚3鱼）与1枚旧靴，六处沿海渔场和适用地图的湖泊。[TB25，第9页]

- 标准地图湖泊替换沙漠，位于允许的内圈；渔场采用官方六个沿海位置，记录其影响顶点与号码。
- 湖泊生产号码已核定为2、3、11、12，不由普通数字随机池分配；开局强盗放棋盘外。
- 第二座开局村庄邻接渔场或湖泊时获得随机鱼筹码；同时邻接多个产出源仍只抽1枚；城市骑士第二座城市也只抽1枚（F0 D03项目裁决）。
- 地图随机化先完成正常布局，再应用已验证的捕鱼配置；相同种子与版本得到相同结果。无合法布局时明确失败，不无限重试。

### 4.2 产出、上限与随机性

骰点命中时，村庄抽1枚、城市抽2枚。按当前行动玩家起顺时针逐人、逐枚执行。鱼面值保密；旧靴抽到立即公开。鱼池耗尽后洗回弃置堆；供应和弃置均空则停止抽取，不能生成新筹码。[TB25，第10页]

持有上限为7枚鱼筹码，旧靴不计入。已满额但仍应获鱼时，每回合至多一次选择弃1枚并换抽，然后停止抽取。建立可恢复的换抽选择，拒绝换抽也能继续结算。不得把7枚误写成7条鱼。[TB25，第10页]

共享随机源调用顺序固定；开启捕鱼才消耗对应随机调用。关闭附加玩法的旧规则执行路径保持原结果。权威存档记录筹码池顺序、弃置、持有人、随机状态、未完成抽取队列与当回合换抽使用标记。

### 4.3 主动行动

| 消耗鱼数 | 基础效果 | 组合效果／限制 |
| --- | --- | --- |
| 2 | 强盗移出棋盘，不偷牌 | 航海模式可选海盗；遵守剧本例外 |
| 3 | 从任一合法对手随机偷1张资源 | 城市骑士可包含商品，不包含进步卡 |
| 4 | 从供应取得1张自选资源 | 不取商品；检查库存与禁获 |
| 5 | 免费建造1条道路 | 航海模式可改为船；仍检查连接、阻挡、棋子供应 |
| 7 | 免费取得1张发展卡 | 城市骑士选择一个合法颜色牌堆随机抽进步卡，不挑具体牌面 |

基础效果见TB25第10页，组合见FCK第1页、FSF第1页。买到的卡遵循原模式的使用时机、持有上限和后续响应。

每次行动独立支付；筹码不能拆分，多付不找零，不能把一次支付的余额用于另一行动。可以多次行动，但必须先完整结算前一行动。[TB25，第10页]

拟定命令流程：本地选效果与目标 → 选择筹码 → 服务器校验授权、时机、目标、供应及筹码 → 原子扣费与执行 → 必要响应 → 胜利检查。目标不存在、供应不足或无合法建造位置时整条命令失败且不扣鱼。随机偷牌抽中被禁获牌属于已有技能的合法结果，沿用B6“不移动、不重抽”裁决，支付不退回；无手牌对手不可选。

TB25写作“自己的回合”。F0 D02固定为本人自由且没有强制待决的掷骰前／行动阶段，产出、弃牌、入侵及其他待决中不可插入；具体阶段门、权限和后续事件以定稿为准。

### 4.4 旧靴与强盗

- 自己的回合可将旧靴交给公开分数不少于自己的另一玩家；比较不计隐藏胜利点卡。指令提交时重新验证分数。[TB25，第10页]
- 旧靴不扣显示分数，仅提高个人门槛。转交后按当前回合的既有胜利窗口重新检查，不能让非行动玩家因门槛变化直接绕过回合限制。
- 强盗可以进入湖泊并阻断湖泊全部号码；不能进入沿海渔场。移出棋盘后，下次正常强盗移动可以重新入场。[TB25，第10页]
- 鱼不是资源／商品，不参与掷7弃牌、玩家交易或强盗偷牌。只获得鱼不影响城市骑士水渠的资源补偿资格。[TB25，第10页；FCK，第1页]

以下均为本项目扩展合同，不称为官方规则。

| 交互 | 拟定处理 | 验证重点 |

| 资源／商品与手牌技能 | 鱼保持独立组件类型；偷牌、均分、交易和手牌计数不包含鱼 | 全部54将97技能按事件类型审查，产出清单 |

| 免费建设与造价 | 5鱼是一次真实建设，支付来源记为鱼；触发适用建造事件，不生成资源实付记录 | 复制、退款、减价不得产生不存在的资源；不递归复制 |

| 貂蝉代操 | 鱼与旧靴属被代操者；控制权限及私密视图沿用现有授权 | 支付、事件和胜利归属不记在操作者账户；断线接管一致 |
| 鲁肃地图事务 | 空间ID不动；湖泊随地形组件交换；海岸渔场固定为空间附着，预检交换后的合法海岸 | 任一附着关系非法则整笔拒绝；港口按现有事务移动 |
| 座次变化 | 捕鱼产出按该次产出开始时锁定的座次顺序；待决中不重新排列 | 保存抽取游标，重连不跳人或重抽 |

地图裁决需补充：湖泊被移动后不能产生未支持的内湖航线；新发现湖泊应走探索事件；港口与渔场允许共用合规顶点，但不得让组件重叠改变点击或计数。若项目未来要让渔场随地形移动，另升规则版本，不静默改变上述合同。

| 兼容身份 | 原规则／场景／三国包版本＋附加模块版本；权威随机状态 |

拟新增命令：`SpendFish`（效果、自己持有的Token IDs、完整目标）、`PassOldBoot`、`ResolveFishReplacement`。命令携带现有唯一ID和状态版本；统一经Execute验证。重复ID返回原结果，不能重新随机或扣费。UI预览不修改任何状态、不消耗随机数。

保存和恢复必须覆盖“已扣鱼、等待后续进步卡响应”等状态。能在一次命令内完成的支付与效果原子完成；必须进入待决的效果保存明确游标，不能恢复后重跑支付。所有非法命令保持状态及随机状态不变。

### 7.3 隐私与兼容

- 本人／合法代操视图：可见自己有权操作的筹码ID、面值及鱼数。
- 对手／旁观公开视图：可见筹码枚数、旧靴和海港分，不发送隐藏面值、鱼池顺序、随机状态或可跨视图关联的隐藏Token ID。
- 支付筹码进入公开弃置后，其面值按桌游规则公开；偷牌日志对无权者只显示数量和参与者。
- AI沿用所属PlayerView；既有AI资源牌权限不自动扩展为可见对手鱼面值。
- 旧存档缺字段按两个开关关闭读取，不重新生成地图。旧客户端不能加入启用新模块的房间；通过能力／版本校验给出明确不兼容提示，不能忽略未知字段后继续游戏。
- 配置改变清除准备状态；重连先恢复授权与视图，再恢复待决UI。玩家主动离房、AI接管、房间无人销毁沿用既有合同。

## 8. 界面、美术与AI

开局仅增加两个勾选项；不兼容地图禁用捕鱼并给一句原因。分数输入显示最终基础目标，旧靴修正显示在持有人详情中。

本人手牌旁放鱼筹码区，点击展开可用行动；先选动作与目标，再预览支付。默认按“浪费最少、同浪费时尽量少用筹码”的确定性策略选取，允许手选。不能把不同组合静默合并为一个整数余额。玩家头像承接偷牌／旧靴目标，棋盘承接建造和强盗／海盗目标。取消提交前选择不扣鱼；强制待决采用明确的完成／放弃选项，避免关闭窗口造成卡局。

海港奖励放现有奖励区，显示持有标记；鱼池和弃置堆只做轻量桌面展示。PC右键说明、安卓长按说明，保持同一桌面布局。渔场与港口、道路、船的命中区分别处理，不用模型碰撞推导规则。

美术清单：海港奖励牌、1／2／3鱼筹码与统一背面、旧靴、六渔场、湖泊。建模必须用Blender MCP，保存生成配方；先验证一个筹码与一处渔场的尺寸、枢轴、遮挡和触控，再批量制作。动画只消费已确认事件，断线快照可直接定位组件，不等待历史动画完成。

AI第一版：估计沿海产出与港口争夺收益；优先考虑立即获胜、解除关键封锁、关键建设与补资源；保留筹码组合与手持上限价值。旧靴倾向交给合法且接近获胜的对手。换抽只基于已知面值和公开规则；策略必须能放弃行动、完成待决与正常结束回合。
