# 手牌比例回归修复 v001

2026-10-13 根据用户反馈修复 v006 手牌明显变长的问题。本轮属于 M6 显示修复，路线图阶段不变。

## 原因与修复

v006 将旧版手牌的强制填满改为完整等比显示，但卡牌贴图此前仍使用 Unity 的非二次幂尺寸取整设置（`nPOTScale: 1`）。宽、高分别取整后，导入贴图的比例与原图不同；等比显示于是放大了这项旧问题，卡牌变得细长，部分木头牌还呈现不同的比例。

47 张资源、商品和进步卡正反面贴图现改为 `nPOTScale: 0`。新增卡牌专用导入器，在重新导入时继续保持原图宽高比；M6 构建入口逐张比较源图与实际导入纹理的比例，偏差超过 0.1% 即阻止构建。木头卡源图为 1030×1526，其余本轮手牌图为 1024×1536，原图像素和来源文件未加工。

手牌仍按既有 108×151 逻辑像素区域布局，完整卡面在区域内等比显示，点击抬起、超量重叠和进步卡预览继续沿用现有操作。游戏规则与 AI 源代码没有修改。

此前 v006 人工检查记录称比例正常，本轮对照确认该检查遗漏了导入缩放造成的失真。旧记录保留，以本修复说明和新验收为更正依据。

## 交付与验证

- 两份 Windows 程序均由固定 Unity `6000.3.25f1` 构建通过，47 张卡牌比例检查通过。
- 87 项既有手牌布局、操作选择和收牌动画回归测试通过，0 失败、0 跳过。本轮没有为外观修改新增 .NET 测试。
- 已优化 AI 修复版的无图形集成检查通过：28 配置、15,078 次断言。
- 两份程序分别通过四类规则的两个独立 Windows 保存／恢复进程；原策略程序的规则与 AI 程序集逐一 SHA-256 核对，与原 v006 程序一致。
- 在 1440×900 独立开发局中实际查看资源、商品和进步卡手牌，点击纸张牌确认只抬起、比例保持；打开“发明”进步卡，确认完整预览的比例正常，并放回手牌。银行牌堆外观也已目视查看。
- 本地验收截图保存于 `.local/m6-ai-v002-card-ratio-v001/manual-review`，包含本人的开发局手牌，不提交到公开仓库。
