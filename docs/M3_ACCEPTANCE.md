## Unity 与独立 Windows 进程

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\development\Build-M3.ps1 -VerifyPlayer
```

固定环境：Unity `6000.3.25f1`，URP `17.3.0`，Windows x64 Mono。构建中在 Unity 实际创建、执行不变量并保存恢复全部 18 个剧本/人数组合。不是仅在新 .NET 中成功构建后推测兼容。

Windows 程序在两个相互独立的后台进程中实际验证：18 个剧本的公开地形与权威恢复、3/4 人正常开局、沿海开局船、拿起/取消、源船与目标两步操作、非法操作原子性、坏存档保留原局、换座清除私有视图与选择、新世界轮流放港与待决恢复、随机继续一致，以及默认/俯视和不同缩放下的点边格拾取。输入由同一 UI 方法及生产命令入口驱动，**未声称通过真实鼠标自动点击或人工操作**。

有效日志：

- [Unity 构建](verification/m3-2026-10-09/unity-build.log)：`CATAN_M3_UNITY_CORE_OK`、`CATAN_M3_UNITY_BUILD_OK`。
- [保存进程](verification/m3-2026-10-09/player-save.log)：场景目录、新世界港口、移船、保存与相机渲染成功标记。

实际 GPU 为 AMD Radeon RX 9070 XT，验证窗口配置为 1440 × 900。URP 相机输出独立的 1440 × 1080 图；已打开检查默认和俯视图，确认整张地图、海域、金矿、山地、船和强盗/海盗可见。这些相机图不含 IMGUI 界面，不作为完整 UI 像素验收或帧率测试。
